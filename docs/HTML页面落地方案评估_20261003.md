# 评估：把桌面 HTML 的选股搬到后端 + 前端照它的格式展示

> 需求（2026-10-03）：**不动它的选股逻辑和代码**，部署到后端；前端按它的格式展示。
> 结论：**技术上完全可行（约 1~1.5 天）**，但有 **3 条必须加的护栏**，否则会误导用户。

---

## 一、结论

| 维度 | 判断 |
|---|---|
| 逻辑能否**原样**搬后端 | ✅ 能。它的逻辑是**纯计算**（一次 HTTP + 打分 + 过滤 + 排序，无状态）⇒ 逐行等价移植，并用**双实现等价性测试**证明"没改逻辑" |
| 前端能否照它格式展示 | ✅ 能。它的结构/样式可 1:1 复刻（勋章卡 Top3、11 列明细表、股票池、筛选条、导出按钮）|
| 部署形态 | ✅ 新建**独立页面** + 新 API（**不动现有页面与接口**，可随时下线）|
| 风险 | ⚠️ 不在技术，在**口径标注**（见第三条）|

## 三、必须加的 3 条护栏（否则会误导用户）

1. **评分必须标来源**
   它的「综合评分 95%」是**启发式公式**，不是 AI 分、也**未做概率校准** ⇒ 若与我们的 AI 评分并列、都叫"概率/涨停率"，用户必然混淆 ✗
   ⇒ 该页统一称「**本页评分**」，页脚注明"启发式公式，非 AI 模型、非概率"（**只改措辞，不改逻辑** ✓）

2. **必须标覆盖范围**
   候选池 = **当日涨幅榜前 200**（实测：我们 5923 只里的绝大多数它看不到 ✗）
   ⇒ 页面顶部一行说明"覆盖：当日涨幅榜前 200"（避免用户以为全市场）

3. **原样保留的已知缺陷要记录在案**（按"不动逻辑"执行，但必须写明）
   - `circMV = f10`（东财 f10 是**量比**，市值应为 f20）⇒ `marketScore` 恒满分
   - 换手公式分母用了量比 ⇒ `activityScore` 几乎恒满分
   - `getBidVolumeRatio()` 恒返回 0（死分支）
   - `priceGt:30` 实为"**剔除 >30 元**"（语义反转）
   - `floatMvGt:100` 比的是量比 ⇒ **永不触发**（死规则）
   ⇒ 净效果：评分权重中 **0.43 被两项钉在满分**，排序实际主要由「竞价涨幅 3~5.5% 优先 + 异动档 + 昨日涨幅」决定。
   实测其 113 只按正确口径重算仅 **20~59 分**，名单画像为「竞价涨幅均值 **+0.2%**、竞价额均值 **524 万**」的低开小票。

## 四、必须做的工程细节（不做会崩）

| # | 事项 | 原因 |
|---|---|---|
| 1 | 服务端代理 + 超时/重试/字段缺失容错 | 东财字段随时可能缺（实测 `f10` 就有 `'-'`）⇒ 原 JS 会算出 `NaN` |
| 2 | 缓存：盘后 300s / 盘中 15~30s | 与刚做完的抢筹优化同思路 |
| 3 | **每次抓取落库快照** | 否则又是一个"只有当天、无法回看/无法回测"的页面 ✗ |
| 4 | **等价性测试**（`node his.js` vs `python his_port.py`，同一份东财 JSON，逐字段断言）| 这是"**没改逻辑**"的**唯一硬证据** |
| 5 | 挂现有 `quota_guard` | 否则接口被刷爆 |
| 6 | 监控：HTTP 码 / 耗时 / 字段缺失率 | 上游一挂，页面全空 |

## 六、我的建议执行方式

1. 后端先做：等价移植 + 等价性测试 + API + 缓存 + 落库 ⇒ **把"逻辑没动"的证明交给你** ✓
2. 前端后做：照它格式复刻成新页面 `/his-pick`（暗色、勋章卡、11 列表、股票池、筛选条）✓
3. 页面顶部一行口径说明（数据源 / 覆盖范围 / 评分性质）✓
4. 后续可选：用落库数据跑**走前向回测**，用数据回答"它这套分数有没有信息量" ✓

> ⚠️ 唯一需要你拍板的：第 3 条护栏里的**措辞**（评分叫"本页评分"而非"概率/涨停率"）—— 这是唯一对"原样"的偏离，但它只影响文字、不影响任何逻辑与数值 ✓
