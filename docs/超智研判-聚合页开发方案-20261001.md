# 超智研判（聚合页）开发方案 · 2026-10-01

> 起因：主人要求「AI预测」更名为**超智研判**（图标「智」），并把里面内容做成**一个聚合页**（参考图 5 块）。
> 本方案先做**数据盘点**（哪些已有、哪些要新建），再给接口设计、口径候选与分期落地计划。
> ⚠️ 结论一句话：**参考图里的 5 块中，3 块能立刻做（零新增上游、零落库）；2 块需要新建"按日快照 + 口径判定"**（曲线与阶段标签）。

## 三、接口与页面设计

### 3.1 新接口（1 个，**零新增上游调用**）
```
GET /api/chaozhi/overview            # 60s 缓存(与 KPL_SENTI_TTL 对齐), 仅盘中轮询
{
  "date": "2026-10-01",
  "scores":  { "emotion": 78, "capital": 69, "promote": 22 },
  "emotion": { "days": ["09-18", …10 天], "zt": [...], "brokenRate": [...], "phase": ["升温","分歧",…] },
  "capital": { "days": [...], "mainNet": [...], "boomRatio": [...], "support": [...] },
  "picks":   [ { "code","name","scoreXgb","scoreLgb","change","risk":"low|mid|high","tag":"关注|观察|待定|谨慎" } ],
  "meta":    { "models": { "xgb": "2026-10-01", "lgb": "2026-10-01" }, "degraded": ["火眼缺失"] }
}
```
数据来源（**全部复用已缓存函数 / 本地文件，不新增一次付费出网**）：
- `scores.emotion` ← `kpl.fetch_sentiment()['strong']`；`scores.promote` ← `build_zt_echelon()`（本身 60s 缓存）
- `scores.capital` ← 板块榜 `strength`/`mainNet` 合成（§四.1）
- `emotion.*` ← 一期：`limit_history` + `ladder_history` 反推；二期：`emotion_snapshot` 表
- `capital.*` ← 一期：`snapshot_bid` 按日聚合 + `fetch_bid_boom()`；二期：`capital_snapshot` 表
- `picks.*` ← 直接读 `aipick/output/predictions_*.json`（xgb）与 `output/lgb/...`（lgb）——**只读文件，不触发推理、不吃 aipick 配额**
- `picks.risk` ← `dev_risk.load_warn_map()` 红/黄 → 三档映射 + `is_st`

### 3.2 前端
- 新路由 `/chaozhi`（name `chaozhi`，`meta.group = 'intraday'`，order 2）→ `views/ChaozhiView.vue`
- 宫格「超智研判」格：**页面建好后改为直跳 `/chaozhi`**（不再弹火眼/金睛子项面板）；页内保留两个入口按钮 → `/aipick`（金睛）、`/aipick-lgb`（火眼）
- 两个图表：复用项目已有 echarts 封装（`utils/echarts.js`，按需引入柱状/折线）
- 轮询：60s 仅盘中（与后端 TTL 同频，满足 `backend/tests/test_polling_ttl_alignment.py`）

## 四、口径候选（**需主人拍板**，各给建议）

### 4.1 资金强度（0~100）
- **候选 A（推荐）**：`资金强度 = 50 + 40 × tanh( 板块主力净额合计 ÷ 两市成交额 × k )`，再用当日 5 档分位映射 0~100。数据用 `board-rank` 全表 mainNet 求和（已缓存）。
- 候选 B：直接取板块榜前 10 的 `strength` 均值。
- 候选 C：用猫爪精选板块 `main_net_amount` 合计（`sector_rotation.py:458`）。

### 4.2 情绪阶段（升温 / 分歧 / 转强）
- **候选 A（推荐，三段式）**：
  - `升温`：涨停数↑ 且 炸板率↓ 且 最高连板↑（三项中 ≥2 项改善）
  - `分歧`：涨停数持平（±10%）或 炸板率升高但最高连板未降
  - `转强`：昨日炸板股今日回封率 ≥ 40%（"反包"信号，已有 `fetch_fanbao_stocks` 可用）
- 候选 B：只用「晋级率 + 炸板率」两指标二维分档（简单、可解释）。

### 4.3 主力关注 / 承接强弱
- **主力关注**：当日板块榜 mainNet 前 3 的板块，其**成分股主力净额合计占两市比**（>阈值 = "主力在关注"）。或简化为**连续 2 日 mainNet 净流入的板块数**。
- **承接强弱（推荐）**：`承接 = 昨涨停股今日竞价平均溢价` ÷ `今日炸板率`（溢价高、炸板低 ⇒ 承接强）；数据齐备（`YestZtPanel` 已在用同一组数）。

### 4.4 风险三档 + 标签
- 风险：`黄 → 中`、`红 → 高`、`ST 或 d3 越线 → 高`、其余 `低`（`dev_risk_daily.warn_level` 已有 + `is_st`）。
- 标签规则（建议）：`关注` = 两模型分数都 ≥80 且风险低；`观察` = 单模型 ≥80 或 风险中；`待定` = 两模型 60~80；`谨慎` = 任一 <60 或 风险高。

| 门禁 | `_verify/nav.spec.js` 的 `ROUTES` 加 `/chaozhi`；若加轮询需满足 `test_polling_ttl_alignment.py`（interval ≥ TTL 且 TTL∈[15,120]） |

## 七、验收标准（真机 390）
1. 五块按参考图顺序渲染；得分卡三个数字均有值（非 0）
2. 两张图各 10 个点，切换 tab 有数据变化；无数据时给明确文案而非空框
3. 个股列表 ≥20 只，每只含 双分数 / 涨幅 / 风险 / 标签；`加入自选` 与 `查看评分详情` 可点
4. 抓配额：进入页面 + 停留 2 分钟，开盘啦出网增量 **= 0**
5. `npm run verify` 0 新增失败；后端相关用例全绿
