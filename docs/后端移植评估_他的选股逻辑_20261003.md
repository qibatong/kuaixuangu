```

        ▼
我们的后端  his_pick_service（**他的逻辑，逐行等价**）
        │   ② computeScore()   —— 原样：5 因子固定权重 0.34/0.32/0.17/0.11/0.06 + 可信度

前端新页面（照他的 CSS/结构：勋章卡 Top3 + 11 列明细表 + 股票池 + 筛选条 + 导出）
```

## 四、三个需要拍板的设计点（我给出建议）

| # | 决策 | 我的建议 | 理由 |
|---|---|---|---|
| 1 | 是否**落库快照** | **落**（每次抓取存一份）| 否则又是一个"只有当天、无法回看/无法回测"的页面 ✗；落库后还能验证它到底有没有价值 |
| 2 | 刷新节奏放哪 | **后端**（9:30 前 30~60s 重算；9:30 后冻结名单、只刷现涨）| 与他的前端语义完全一致，只是把"何时重算"从浏览器移到服务端 ✓ |
| 3 | 前端放哪 | **先做预览页**（不动现有竞价选股）→ 你看过再决定是否替换 | 替换主页风险大，预览页零风险 ✓ |

## 五、风险清单（都是"已知并接受"型，但必须写明）

| 风险 | 影响 | 处理 |
|---|---|---|
| 他评分公式 5 处字段误用（`f10`=量比当市值、换手分母错、量比恒 0、`price>30` 语义反转、`f10>100` 死规则）| 评分权重中 **0.43 恒满分** ⇒ "95 分"不代表 AI 意义上的高分 | **原样保留** ✓ 需在页内注明"本页算法分"，避免与我们 AI 评分混淆 |
| 候选池仅**涨幅榜前 200** | 覆盖面窄（实测我们 5923 只中绝大多数它看不到）| 页内注明覆盖范围 |
| 东财接口偶发缺字段/限流 | 单次可能无数据 | 后端容错 + 缓存上一次 + 空态提示 |
| 与四线名单/AI 评分并存 | 用户看到两套口径 | 独立页面/独立 tab，互不混排 |
| 依赖非官方 token（`ut=`）| 上游若变更需跟进 | 监控 + 可快速改服务端（这就是后端化的好处 ✓）|

3. **接口验收**：`GET /api/his-pick` 返回 `{list, medals, pool, meta}`，含缓存命中耗时与快照时间 ✓
