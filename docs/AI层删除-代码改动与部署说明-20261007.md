## 〇、两个连带问题的答案（先答，因为它们改变了结论）

### ① 「竞价选股没有用后台这套评分系统吧？」—— ❌ **在用，而且是主链路**

`picker/pipeline.py::_load_strength` 里明确调用（且线上开关是开的）：

```python
if not bid_strength.enabled():        # settings use_bid_strength —— 线上值 = "1"(开)
    return {}
st = bid_strength.load(list(codes), date=ctx.date)   # ★ 竞价选股主链路调用
```

线上 `settings.use_bid_strength = "1"`（实测读出）。所以：

```
竞价选股(主链路) ─┐
个股详情 /api/stock/detail ─┼→ bid_strength.load → _fill_ai → ai_predict._market_prob_map
                          ┘                                    （全市场推理 4.417s，结果×0 丢弃）
```

⇒ **AI 层那 4.4s 是**（至少）**两个入口共用的**，删除收益比预想的大得多：
它从**竞价选股主链路**和**个股详情**上一起消失。

### ② 「aipick 这个数据，超智在用什么？」—— 4 项，全部**只读文件**、与评分链路无关

| 超智用到的 aipick 资产 | 用途（`chaozhi.py`） |
|---|---|
| `output/predictions_<date>.json` | **金睛**模型分数（`ai_prob` → `scoreXgb`） |
| `output/lgb/predictions_<date>.json` | **火眼**模型分数（→ `scoreLgb`） |
| `aipick.db` 的 `features` 表 | 9:25 定格快照 + 昨日侧标签（连板/涨停等） |
| `aipick.db` 的 `pick_daily` 表 | 每日 9:28 落库：可买性分级 / 是否一字 / 封板结果 |

`chaozhi.py` 模块注释写明：**「只读文件 ⇒ 不触发推理、不吃 aipick 配额」**，并刻意
**不复用 `/api/aipick/data`**（那个接口带 `quota_guard("aipick")`，免费用户 1 次/日）。

⇒ **删掉评分里的 AI 层，对这 4 项零影响。** 超智页完全不受牵连。

## 一、改了什么

**指令解读**：删掉评分里的 AI 层；它原来的 0.25 份额归量比 —— 量比单独占满时
**权重写 0.75 即可**（`_compose` 会自动归一 ⇒ 归一后即 100%，写 1.0 也等价）。

| 文件 | 改动 |
|---|---|
| `app/services/bid_strength.py` | 删 `BidStrength.ai` 字段、`_fill_ai()` 函数、`load()` 中的调用、`_compose()` 的 `w_ai×ai_score` 与 `ai_default` 项；`score_one`/`score_one_live_ff` 去掉 `st.ai` 实参；模块注释补 v8 演进史 |
| `app/services/scorer.py` | 默认配置删 `w_ai` / `ai_buckets` / `ai_topn` / `ai_default` 四个键（`w_vol_ratio` 保持 0.75） |
| `app/main.py` | 删 AI 概率图预热线程启动（`_ai.start_ai_prewarm()`），原位留注释说明来龙去脉 |
| `app/services/ai_predict.py` | **整文件删除**（孤儿：唯一消费方就是 `_fill_ai`） |
| `tests/test_bid_strength.py` | 重写：删 `test_ai_buckets`，**新增 `test_ai_layer_is_gone` 防回退钉子**；权重改 0.70+0.30（和=1，便于断言） |
| `tests/test_intraday_ff.py` | 替身配置同步（0.45+0.30+0.25 → 0.70+0.30），期望值恰好不变（见下） |
| `tests/test_ai_predict.py` | 随模块删除 |

**为什么保留 `w_ff` 而不一起删**：主人只拍板删 AI。净额层是独立开关（`w_ff=0` 表示不参与，
恢复只需调回 0.30），且它牵连 `api/stocks` 的盘中加分路径，不属于本次范围。

### 一个值得记的细节：期盘加分的期望值**恰好不变**

`test_intraday_ff.py` 原本算的是：

```
warn_static = 0.45×0.55 + 0.30×0.35 + 0.25×0.35 = 0.44
warn_live   = 0.45×0.55 + 0.30×1.00 + 0.25×0.35 = 0.635
bonus = 0.17 × (0.635 − 0.44) × 100 = 3.315 → 79 + 3.315 → 82
```

删掉 AI 项后权重和变 0.75，归一化成了 0.6/0.4，价差变 0.26 → **结果变 83**（测试报
`assert 83 == 82`，这是我引入的唯一失败）。把测试配置的权重补成 0.70+0.30（和=1）后：

```
warn_static = 0.70×0.55 + 0.30×0.35 = 0.49
warn_live   = 0.70×0.55 + 0.30×1.00 = 0.685
bonus = 0.17 × 0.195 × 100 = 3.315     ← 与删除前逐字相同
```

**原因**：原式里 AI 项 `0.25×0.35` 在 static / live 两侧**完全相同**，做差分时自动抵消。
⇒ **线上盘中加分行为不受本次删除影响。**

## 四、顺带记下的两点

1. **`w_ai` 这个键不能"直接删配置就算了"** —— `_cfgf(fac,"w_ai",0.25)` 带默认值，
   光删配置会让它**回退到 0.25 反而启用**。本次是**连代码读取一起删**，才真正安全。
2. **本地 backend 与生产 backend 在改动前是一致的**（本轮 diff 验证：三个文件的差异
   全部来自本次改动，无历史漂移）。这点以后每次部署前都值得复核一次。
