# 诊断：东财 clist「分页失败」与竞价窗口熔断自锁

> 日期：2026-09-19（周六，非交易日，**全程只读**）
> 起因：主人质疑「老是说服务端被限流、采集定格快照有异常，却找不到解决方案」
> 结论：**不是限流。是我们自己的分页越界误判，把东财数据源每天在 09:15 熔断 535 秒。**

## 一、结论摘要

| 项 | 结论 |
|---|---|
| "东财限流 / 被墙" | ❌ **证伪**。主力域名 `push2dycalc` 全程畅通，无频率限制特征 |
| 真实失败 | 分页请求**超出该板块真实页数**后，东财返回 `rc=102 / data:null`（= "无更多数据"），被代码当成异常 |
| 后果 | 触发「整批放弃」+「数据源熔断」，**每天 09:15:12 → 09:29 熔断 535 秒**，覆盖整个竞价窗口 |
| 定格数据 | `9_15` / `9_20` / `9_24` / `9_25` 四个时点**全部降级为兜底源**（开盘啦 + TickPlus） |
| 17% 异动因子 | TickPlus **无 f630** ⇒ 定格链路 `warn_type` 必然全 0 |

## 二、症状量化（生产 `app.log`）

| 指标 | 9/17 | 9/18 |
|---|---|---|
| `全市场拉取分页失败` | 124 | **9332** |
| 错误类型 | 「东方财富接口返回异常」**清一色** | 同 |
| 整批快速失败 | — | 8 |
| 熔断相关日志 | — | 85 |

**失败页号的分布是决定性线索**：

```
page 1~18 : 0 次失败
page 19~25: 各 149 次
page 26~28: 各 323 次
page 29~30: 各 513 次
```

完美按页号分界 ⇒ **不是随机抖动、不是频率限流**。

## 三、逐页实测（生产机，串行 150ms，排除频率因素）

| fs | total | 真实页数 | 末页 | 首个 `rc=102` |
|---|---|---|---|---|
| `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` 四板全市场 | 5560 | 28 | p28(160只) | **p29** |
| `m:1+t:2,m:0+t:6` 沪深主板 | 3487 | 18 | p18(87只) | **p19** |
| `m:0+t:80` 创业板 | 1452 | 8 | p8(52只) | **p9** |
| `m:1+t:23` 科创板 | 621 | 4 | p4(21只) | **p5** |

越界页返回体：`{"rc":102,"rt":1,"svr":...,"data":null}`
⇒ 这是东财的**正常"翻到底"语义**，等价于"没有更多数据"，**不是错误、不是风控**。

## 四、因果链（完整）

```
[配置] SPOT_MAX_PAGES = 30（固定，与板块无关）
        ↓
[09:15:12] _fetch_market_map(full=True) 三分区并发采集
        ↓  cyb 真实 8 页、kcb 真实 4 页，但都被打到第 30 页
        ↓  越界页 rc=102 → _fetch_clist_page 抛 RuntimeError
        ↓  done_fail(22/26) ≥ done_ok(8/4)
        ↓  ① 整批放弃 → 该分区走腾讯兜底
        ↓  ② _record("eastmoney_clist", False) + down_threshold=1 → 熔断 60s
        ↓
[09:15:12 ~ 09:29:01] 熔断期 535 秒（9/17 为 546 秒，两天启动时刻完全一致）
        ↓  期间 _check_circuit() 为真 → 所有东财 clist 请求"快速失败"
        ↓
[09:24:45] 秒级采样全失败 → 开盘啦兜底仅 244 只
[09:25:28] 9_25 定格采集三分区齐报「熔断中」→ 东财 0 只
[09:25:29] 开盘啦 277 + TickPlus 5555 → "补值0项" → 定格 5555 只
        ↓
[结论] 9_25 定格（名单权威）= 兜底源口径；TickPlus 无 f630 ⇒ warn_type 全 0
```

> 注：TickPlus 是竞价第二源（独立域名），只提供 `bid_change / bid_amt` 等竞价字段，
> **不提供东财 f630**。所以"名单齐全"与"异动因子有效"是两件事。

**9/18 09:25 定格那一刻的原始日志**：

```
09:25:28  [快照采集] 触发时点窗口 tp=9_25
09:25:28  快照拉取失败 market=hs  full=True err=东财数据源熔断中, 快速失败
09:25:28  快照拉取失败 market=cyb full=True err=东财数据源熔断中, 快速失败
09:25:28  快照拉取失败 market=kcb full=True err=东财数据源熔断中, 快速失败
09:25:28  [快照采集] 东财全分区失败, 尝试开盘啦竞价榜兜底
09:25:29  [快照采集] 开盘啦兜底: 委买200只 爆量100只 合并去重277只
09:25:29  [快照采集] 双源合并 东财277只 + TickPlus5555只 → 补票5278只 补值0项 → 合计5555只

```

- `东财277只` 其实是**开盘啦那 277 只**被计入"东财"计数；
- `补值0项` = TickPlus 只新增股票名单，**一个字段值都没补**；
- 行数 5555 看着"健康"，**掩盖了口径降级** —— 这就是"采集定格快照有异常"的真身。

## 六、修复方案（三处）

| # | 位置 | 改法 | 理由 |
|---|---|---|---|
| 1 | `fetcher._fetch_clist_page` | `rc==102 或 data 为空` → **返回 `[]`**（"到底"语义），不抛异常 | 调用方 `if not diff: break` 自然终止，不再空打后续页 |
| 2 | `fetcher.fetch_eastmoney_all` | 页数按首页返回的 `total` 动态算 `ceil(total/pz)` | cyb 只打 8 页、kcb 只打 4 页，**无越界页** |
| 3 | `_HEALTH["eastmoney_clist"]["down_threshold"]` | `1` → `3` | 抖动保护，单批失败不再熔断 60~600s |

### 预期收益（实测口径）

- 日志噪音 9332 条/天 → **≈ 0**
- cyb/kcb 回归东财真源：**f630 非 0 从 0 → 928 只**（cyb 777 + kcb 151）
  ⇒ **880 只 ≥3 档票**（0.6~1.0 权重）从"被当 0 档"恢复
- 竞价窗口不再撞熔断 ⇒ 定格回归东财口径
- 每天减少约 9332 次无效外网请求

### 风险与回滚

- 改动仅涉及"翻到底"的分支语义与页数计算，**不触碰任何字段解析**。
- 回滚：三处均为独立小函数，`git revert` 即可；**无数据迁移**。
- 验证：新增单测（`rc=102` → 空列表、页数按 `total` 收敛）+ 测试机全量回归。
