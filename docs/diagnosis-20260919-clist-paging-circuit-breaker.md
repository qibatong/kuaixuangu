## 一、结论摘要

| 项 | 结论 |
|---|---|
| "东财限流 / 被墙" | ❌ **证伪**。主力域名 `push2dycalc` 全程畅通，无频率限制特征 |
| 真实失败 | 分页请求**超出该板块真实页数**后，东财返回 `rc=102 / data:null`（= "无更多数据"），被代码当成异常 |
| 后果 | 触发「整批放弃」+「数据源熔断」，**每天 09:15:12 → 09:29 熔断 535 秒**，覆盖整个竞价窗口 |
| 定格数据 | `9_15` / `9_20` / `9_24` / `9_25` 四个时点**全部降级为兜底源**（开盘啦 + TickPlus） |
| 17% 异动因子 | TickPlus **无 f630** ⇒ 定格链路 `warn_type` 必然全 0 |

## 四、因果链（完整）

```

        ↓
[09:15:12] _fetch_market_map(full=True) 三分区并发采集

        ↓  期间 _check_circuit() 为真 → 所有东财 clist 请求"快速失败"

        ↓
[结论] 9_25 定格（名单权威）= 兜底源口径；TickPlus 无 f630 ⇒ warn_type 全 0
```

## 六、修复方案（三处）

| # | 位置 | 改法 | 理由 |
|---|---|---|---|
| 1 | `fetcher._fetch_clist_page` | `rc==102 或 data 为空` → **返回 `[]`**（"到底"语义），不抛异常 | 调用方 `if not diff: break` 自然终止，不再空打后续页 |
| 2 | `fetcher.fetch_eastmoney_all` | 页数按首页返回的 `total` 动态算 `ceil(total/pz)` | cyb 只打 8 页、kcb 只打 4 页，**无越界页** |
| 3 | `_HEALTH["eastmoney_clist"]["down_threshold"]` | `1` → `3` | 抖动保护，单批失败不再熔断 60~600s |

# 九、修复落地与验证（v4.11.32，2026-09-19）

## 9.1 实际改了什么

| # | 位置 | 改动 |
|---|---|---|
| 1 | `fetcher._fetch_clist_page` | 新增 `_EM_RC_END=102`；`rc in (0,102)` 或 diff 为空 → 返回**空 `_ClistPage`**（"到底"语义），**不再抛异常**；只有 rc 既非 0 也非 102 才抛（真异常防线）。新增 `_ClistPage(list)` 携带 `total`，保持既有 list 语义（`len/extend/真值`零改动） |
| 2 | `fetcher.fetch_eastmoney_all` | 第 1 页**串行**取回 `total` → `_page_count()` 算真实页数 → 只并发请求必要页（**+1 探测页**兜住 total 少报）；拿不到 total 则回退 `SPOT_MAX_PAGES`（老行为兼容）；**首页为空 = 真故障**（页 ≥2 为空才是"到底"） |
| 3 | `fetcher.fetch_eastmoney` | 补偿：单页接口保持原"空即异常"契约（`_fetch_clist_page` 改为不抛后，此处显式判失败） |

🔴 **第 3 处熔断阈值（`down_threshold` 1→3）我主动撤回了**。重新读代码后确认：自 2026-09-10 起
熔断已改为**按整批判定**（`done_fail >= done_ok`，即"过半页失败"），单页抖动本就不会熔断 ——
阈值 1 只会在"整批过半失败"时触发，**那正是真故障，应当尽快切兜底源**。改成 3 反而拖慢真故障的
降级速度，且会打红 4 个既有用例。故**不改**。
