## 三、顺带修正的两处「语义混淆」（需主人知晓）

原实现用**涨跌色**表达**状态**，同一颜色承担两种相反语义：

```css
/* 优化前 */
.czh-health.h-good { color: var(--down); }   /* --down = 跌色，却用来表示"健康" */
.czh-tag.t-good    { color: var(--down); }   /* 同上 */
```

改为规范里的 **`--success-text` / `--success-bg`**（成功绿）。

⚠️ **这会带来可见的颜色变化**：`--down`(#00c864) → `--success-text`(#c0e8a0)。
两者都是绿，但后者更柔和；若主人希望保持原色，把这两行改回 `var(--down)` 即可（其余改动不受影响）。

## 六、追加：字号档位压缩（主人 2026-10-06："一个页面就用了 8 档字体，太多了"）

### 实测：超智页原用 **6 档**（对比其他页面确实偏多）

| 文件 | 档位 |
|---|---|
| `ChaozhiHome.vue` | 4 档（xs 9 处 / sm 20 处 / **xl 1 处** / **display 1 处**）|
| `SentimentPanel.vue` | 4 档（xs 6 / sm 5 / **md 2** / **base 1**）|
| **合计** | **6 档** |

**对照其他页面**：`LadderView` 4 档、`YijinerView` 4 档、`AipickReport` 5 档、`AuctionView` 5 档。

### 根因：同一个语义（"数值"）散在 4 个不同档位

- `ChaozhiHome` 的 KPI 大数字 → `--fs-display`(24px)
- `SentimentPanel` 的指数点位 / 情绪数值 → `--fs-md`(15px)
- 手机上情绪数值 → `--fs-base`(14px)
- 板块涨幅、龙头涨幅等行内数字 → `--fs-sm`(13px)

### 压缩后：**4 档**（与其他页面持平）

| 档位 | 值 | 承担的角色 |
|---|---|---|
| `--fs-display` | **24px / 700** | **关键数值**（KPI 量能/红盘率/竞价涨停…）—— 全页仅此一档 |
| `--fs-lg` | **16px / 700** | 区块标题 · 指数点位 · 情绪卡数值 · 小标题 |
| `--fs-sm` | **13px** | 正文 / 表格 / 标签 / 行内数字 |
| `--fs-xs` | **12px** | 角标 / 单位 / 同比副行 / 口径说明 |

**具体改动（5 处）**：

| 元素 | 优化前 | 优化后 | 说明 |
|---|---|---|---|
| `.czh-t` 区块标题 | `--fs-xl`(18px) | **`--fs-lg`(16px)** | 18px 全页只有标题在用，为它单占一档不划算；降到 16px 后靠**字重 700 + 最高对比色**区分主次 |
| `.idx-px` 指数点位 | `--fs-md`(15px) | **`--fs-lg`(16px)** | 反而**大了 1px**、更醒目 |
| `.emo-val` 情绪数值 | `--fs-md`(15px) | **`--fs-lg`(16px)** | 同上 |
| 手机 `.emo-val` | `--fs-base`(14px) | **`--fs-sm`(13px)** | 不再专设一档；有 700 字重兜底，手机可读 |
| `.czh-v` KPI 大数字 | `--fs-xl`(18px) | `--fs-display`(24px) | 见第二节（同时修正了"数字与标题同号"的层级问题）|

**验证**：源码并集 `--fs-display / --fs-lg / --fs-sm / --fs-xs` = **4 档**，与 `LadderView`/`YijinerView` 持平。

> 说明：产物 CSS 里仍能搜到 `--fs-md`，但那是 `main.css` 中**其他组件**的类（`.medal-code` 勋章、`.pool-stock-code` 股票池），**不属于超智页**。

**上线记录**：入口 `index-BhXZERHM.js`，备份 `dist_bak_20261006-233232`。

## 七、再收敛：4 档 → **3 档**（主人 2026-10-06："4 层也多了，你评估 3 层或者 2 层"）

### 评估两个方案

**关键依据 —— 本页最初的设计意图**（`ChaozhiHome.vue` 文件头注释原文）：

```
样式：沿用主站令牌，字号**只用 2 档**（--fs-sm 13px 内容 / --fs-xl 18px 标题与关键数字）。
```

⇒ 4 档是后续几轮为局部强调**逐个加上去**的，用户要的是回到原点。

| 方案 | 档位 | 评估结论 |
|---|---|---|
| **2 层** | 13px + 18px | ❌ **不推荐**：角标、单位、同比副行、口径说明被迫与正文同为 13px ⇒ **全页没有次要层级**，次要信息抢主信息注意力，反而更难读。原设计能成立，是因为当时还没有后来新增的"同比副行 / 口径说明 / 角标"这些内容 |
| **3 层** ⭐ | **12 + 13 + 18** | ✅ **采用**：保住了"次要信息"的降级通道，又比 4 档少一层 |

### 最终 3 层（已实施）

| 档位 | 值 | 承担的角色 | 与相邻层的区分手段 |
|---|---|---|---|
| `--fs-xl` | **18px / 700** | **区块标题 + KPI 关键数值**（同档） | 字重 700 + `--text-main` 最高对比 |
| `--fs-sm` | **13px** | 正文 / 表格 / 标签 / 指数点位 / 情绪数值 | — |
| `--fs-xs` | **12px** | 角标 / 单位 / 同比副行 / 口径说明 | 颜色降级（`--text-dim` / `--text-muted`）|

**改动（4 处）**：

| 元素 | 上一版 | 本版 | 说明 |
|---|---|---|---|
| `.czh-t` 区块标题 | `--fs-lg`(16px) | **`--fs-xl`(18px)** | 回到原始设计 |
| `.czh-v` KPI 数值 | `--fs-display`(24px) | **`--fs-xl`(18px)** | 与标题**同档**，靠 700 字重 + 最高对比色区分 —— 这是"少档位但不丢层级"的正解 |
| `.idx-px` 指数点位 | `--fs-lg`(16px) | **`--fs-sm`(13px)** | 降档后靠 **700 字重**保持可读 |
| `.emo-val` 情绪数值 | `--fs-lg`(16px) | **`--fs-sm`(13px)** | 同上 |
