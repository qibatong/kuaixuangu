# 九、2026-10-03 追加：修一个真 bug —— 竞价选股页底部多出一整块「竞价优选」

## 现象（主人发现）

打开**竞价选股**，滚到底部，会看到**竞价优选（一进二）的完整内容** ✗

## 根因（我的移植引入）

`StockView.vue` 的左栏内容是 **v-if / v-else-if 瀑布**，但 `leftTab === 'auction'`（竞价选股）由
**上方一个独立的 `v-if`** 承载（`<div v-if="leftTab === 'auction' && 会员守卫" class="his-pick-host">`）
—— 它**不在这条瀑布链上** ✗

⇒ `leftTab === 'auction'` 时，瀑布链上从第一个条件（`legacy-auction`）到 `zhpick` **全部为 false**
⇒ 直接落进**链尾 `v-else` = `YijinerView`（竞价优选）** ⇒ HisPickPanel 与 YijinerView **同时渲染** ✗

> 注：这不是"会员/配额守卫不满足才出现"，而是**只要在竞价选股 tab 就必然出现**（守卫只决定 HisPickPanel 渲不渲染）。
> 排查过程中我一度换成"守卫不满足才漏"的假设，用源码逐行核对后否定 ✓（`v-else` 是无条件兜底）。

## 为什么只有这一处漏

链上已显式列出的取值：`legacy-auction` / `spot` / `aipick` / `aipick_lgb` / `yijiner` / `zhpick`
`TAB_KEYS` 全集 = `['auction','spot','aipick','aipick_lgb','yijiner','zhpick']` ⇒ **只有 `auction`（和现不可达的 `legacy-auction`）不在链上** ✓
所以只此一处、只此一页 ✓

## 修法

在链尾兜底之前插入**显式吞掉分支**（空模板），只让真正的未知 tab 继续走兜底：

```html
<!-- 已由上方独立 v-if 的 HisPickPanel 承载 ⇒ 显式吞掉，避免落进兜底优选分支 -->
<template v-else-if="leftTab === 'auction' || leftTab === 'legacy-auction'"></template>
<YijinerView v-else :embedded="true" />
```

## 核验

- 源码层：分支已插入（`StockView.vue:194`）✓
- 产物层：新入口 `index-C3qg9dtn.js`｜上线包中 `legacy-auction` 分支 **3 处** ✓
- 线上：首页 HTTP **200** ✓｜新入口 **200** ✓｜上传包 md5 与服务端**一致** ✓
