## 四、实机实锤的三条 P0（并对源码结论做订正）

### P0-1 横滑后**名称列被推出屏幕**（已实锤，且比源码判断更严重）

| 2 现涨 | 52 | 211 | 131 | — |
| … | | | | |
| 5 **评分** | **28** | 357 | 277 | **「94分」在 28px 内换行成两行**（截图可见） |
| 6 可信 | 28 | 385 | 305 | 同上（`83%` 换行） |
| 7 概念 | 48 | 413 | 333 | 半截 |

- 所有 `td` 实测 `position: static`（**无 `left` 冻结列**），仅 `th` 有 `top` sticky。
- **订正**：上一版报告我按"名称列仍可见、只溢出 19%"降温，**实测不成立** —— 名称列 left 变 −45、且被压到 176px（桌面 163px 之外的挤压来自列宽重分配）。
- 附带发现：**窄屏列宽畸变** —— 名称 176px 但 **评分/可信各只有 28px**（桌面 65/80px），数字必然折行。这比"丢身份"更早暴露：**盯盘时要读的评分列在手机上已经不可读**。

### P0-2 右栏多日表：**308 行 / 2,053 单元格常驻，且无虚拟化**（实锤）
- `document.querySelectorAll('.msd-row').length = 308`、`.msd-cell = 2053`、`.msd-row span = 2040`（3 列 × 每日 8 格）。
- `.msd-row` 计算样式：`content-visibility: **visible**`、`contain-intrinsic-size: **none**` ⇒ **确实没有虚拟化**（源码里只有左表 `StockTable.vue:468` 有）。
- `.msd-body` `overflow-y: visible`（整页滚）⇒ 全部行参与布局；且**待机也在渲染**（窄屏看不见时同样常驻）。
- 结合字号（下节）：**308 行 × 10.24px 字号**，是"性能 + 可读性"双重压力点。

### P0-3 数字变化零反馈、涨跌颜色唯一编码（实锤）

## 七、更新后的 Top 3（按"交易者更快更准"排序）

1. **右栏多日表：限行 300 + `content-visibility:auto`（含窄屏 `v-if`）** —— 308 行/2053 cell 实锤，且待机也渲染；这一步同时缓解滚动掉帧与内存。
2. **窄屏列宽与冻结列**：≤480 隐藏序号/可信列 + 评分列 `min-width:44px;white-space:nowrap`；给名称列加 `position:sticky;left:0;background:var(--bg-panel-solid)`（桌面无需，仅在 `≤768` 生效）。收益：手机上"评分不再折行 + 横滑仍知道是哪只票"。
3. **数字变化背景闪 + ▲▼ 方向符号**：`▲▼`=0 实锤；配合水印降到 `.10`，让"变了没有 + 涨跌方向"一眼可辨（且色弱可用）。

> 次要但性价比高：`logo.jpg` 58 KB 压缩、`auction-overview` 三连请求去重、`prefs` 401 静默 —— 三项合计改动 <1 小时，直接改善首屏。
