# 线上 AI 因子权重：是否在用 / 能否删除（2026-10-07）

> 主人问：「线上 AI 因子权重，这个你看下目前有使用吗。是否可以删除」
>
> **一句话结论：权重 0 = 确实没在用，但那个 `0` 恰恰是"关掉它"的开关——删了反而会把它打开。**
> 真正可以省掉的是它背后那条**每天白烧 4.4 秒**的内联推理链路（做法见第四节）。

---

## 一、当前配置：AI 确实是 0

`settings.scoring.factors.bid_strength`（线上实测读出）：

```json
{ "w_vol_ratio": 0.6, "w_zb": 0.4, "w_ai": 0.0, "w_ff": 0.0,
  "ai_buckets": [["0.900","1.01",1.0], ["0.823","0.900",0.85], ["0.700","0.823",0.7]] }
```

归一后实际生效的子权重（`_compose` 自动归一，实测）：

```
w_vol_ratio  0.6 / 1.0 = 0.60      ← 量比分档
w_ff         0.0 / 1.0 = 0.00      ← 竞价主力净额（已移除）
w_ai         0.0 / 1.0 = 0.00      ← AI 层（本次核查对象）
w_zb         0.4 / 1.0 = 0.40      ← 竞价昨比
```

合成公式（`bid_strength.py:421`）：

```python
return max(0.05, min(1.0, w_vol*vol_score + w_ff*ff_score + w_ai*ai_score + w_zb*zb_score))
```

⇒ `w_ai = 0` ⇒ `w_ai * ai_score ≡ 0` ⇒ **AI 层对评分零贡献**，当前评分 = **0.6×量比档 + 0.4×昨比档**。

**而且这是有意为之**，不是异常 —— 代码注释（`bid_strength.py:374-376`）写明：

```
启用方式(纯配置): `w_zb` 写 0.40 等, 并把 `w_ai` 调 0(去掉 AI 层)/`w_vol_ratio` 调 0.60。
```

线上配置与该指引**逐字一致**（`w_zb 0.4` / `w_ai 0` / `w_vol_ratio 0.6`）。

## 二、⚠️ 关键：`w_ai: 0` 这个键**不能删**

`bid_strength.py:385` 读权重用的是**带默认值**的取值：

```python
w_ai = _cfgf(fac, "w_ai", 0.25)      # ← 键不存在时回退到代码默认 0.25
```

⇒ **若把 `w_ai` 从配置里删掉，会回退到默认 0.25 ⇒ AI 层反而被启用**，评分口径当场改变
（量比 0.6 / 昨比 0.4 / AI 0.25，归一后 AI 占 20%）。这是**反向回归**。

**⇒ 保留 `w_ai: 0.0` 是正确做法。** 同理 `w_ff: 0.0` 也是开关语义（注释：恢复只需调回 0.30）。

## 三、但取数链路确实在"白干活"（实测）

`_fill_ai` 是**无条件调用**的，不看权重（`bid_strength.py:155`）：

```python
if out and filled_date:
    _fill_ai(out, filled_date)      # ← w_ai=0 也照跑
    _fill_zb(out)
```

`_fill_ai` → `ai_predict.ai_score_map` → `_market_prob_map(date)`，而后者冷启动要做
**全市场取数 + 猫爪补字段出网 + pandas + 全市场 predict_proba**。线上实测耗时：

```
_market_prob_map(2026-09-30) → 5561 只, 耗时 4.417s      ← ★ 冷启动
_market_prob_map(2026-10-07) → 0 只,    耗时 0.002s      （非交易日，无快照）
```

**结果最后乘 0 丢掉。**

**消费方核查**（全项目 grep `_market_prob_map` / `ai_score_map`）：

| 位置 | 性质 |
|---|---|
| `bid_strength.py:256` | **唯一实际调用方**（`_fill_ai`） |
| `main.py:133`、`bid_strength.py:42` | 仅注释 |

`main.py:132-136` 说明预热线程的来由：

```
个股详情 /api/stock/detail 为单只票算评分时会触发 ai_predict._market_prob_map 的
**全市场**推理，冷启动实测 4.8~5.1s …… 后台线程保持该缓存常热 ⇒ 用户请求恒命中。
```

⇒ 即：**详情页算评分 → 走 `bid_strength` → 顺带触发这 4.4 秒全市场推理**，
而 `w_ai = 0` ⇒ 算完乘 0 丢掉 ⇒ **预热线程每天在为一个不参与评分的结果保温**。

## 四、可以做的（最小改动、可一键恢复）

**改法**：在 `bid_strength.load()` 里按权重短路 + 预热线程同条件启停。

```python
if out and filled_date:
    fac = (scorer.get_scoring_cfg().get("factors") or {}).get("bid_strength") or {}
    if _cfgf(fac, "w_ai", 0.25) > 0:        # ← 新增：权重为 0 时不取数
        _fill_ai(out, filled_date)
    _fill_zb(out)
```

| | 收益 | 风险 |
|---|---|---|
| 评分正确性 | **完全不变**（结果本来就乘 0） | 无 |
| 省开销 | 每天 1 次全市场推理（4.4~5s，含出网 + pandas） | — |
| 详情页 | 少一个冷启动诱因 | 无（本来也有缓存） |
| 可回退 | `w_ai` 调回 0.25 即恢复 | — |

⚠️ **不建议**直接把 `_fill_ai` / `ai_score_map` / `ai_buckets` 代码删掉：它们是**设计好的可恢复开关**
（`w_ai` 调回即用），删了将来重新启用 AI 层要重写。

## 五、与 AI 无关、**绝不能删**的部分

以下都是 `ai_prob` / aipick 生态，**与评分链路独立**，超智页正在使用：

| 资产 | 用途 |
|---|---|
| `predictions_<date>.json` / `lgb/...` | 超智页**机会清单**（金睛 / 火眼两列、综合评分排序） |
| `aipick` 采集 / 预测 / 标签 / 训练调度 | 名单页数据来源 |
| 前端 `ai_prob` 展示与徽章 | aipick 名单页 |

⇒ 停掉评分里的 AI 层**不会**影响上述任何一项。

## 六、结论

| 问题 | 答案 |
|---|---|
| AI 因子权重在用吗？ | **没在用**（`w_ai = 0.0`，归一后 AI 占比 0） |
| 权重键能删吗？ | **不能** —— 删了回退代码默认 **0.25**，AI 层反而启用 |
| 那能删什么？ | **能停掉它的取数链路**：`_fill_ai` 按权重短路（省 4.4~5s/天，评分零变化） |
| aipick 数据能删吗？ | **不能** —— 超智页机会清单独立依赖 |
| 本次是否已改？ | **未改**，等主人拍板（属代码改动） |
