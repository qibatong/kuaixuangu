## 八、【已实施并上线】P0-③ 现涨/爆量改「按代码点查」（2026-09-29 11:40~11:47，测试机 + 生产机）

### 先量化，结果推翻了清单 1.4 的写法

清单 1.4 原写「竞价时段现涨走东财实时（`stats._apply_change_stats`）⇒ 改为复用 spot 预热缓存」。实测（生产日志 2026-09-29）：

| 量化项（近 12 分钟 / 竞价窗口 09:14~09:29） | 实测 |
|---|---|
| `三时点/快照 现涨(实时)覆盖 51 只`（每 30s 一次） | 每次**都命中 spot 缓存**（`全市场行情map命中` 84 次 / 出网 0 次） |
| ⇒ 结论 | **1.4 已经是现状**（现涨走的就是 spot 缓存），无需改 |
| 但同一窗口 `全市场行情map刷新 … 共5561只` | **8 次**（每次 ~33 个 HTTP 请求 ≈ 264 请求） |
| 同窗口 `429\|限流` 日志 | **241 条** |
| 真正的原因 | 现涨只需 **51 只**、爆量只需 **几十~几百只**，却**每次拉全市场 5561 只（33 请求）**，且在**用户请求线程**里同步做 |

### 改法：复用项目现成的按代码点查（`fetch_raw_by_codes`，东财 `ulist.np/get`）

| 改动 | 内容 |
|---|---|
| 新增 `fetcher.fetch_spot_quote_map_by_codes(codes)` | 逐 code 缓存 60s（= SPOT_CACHE_TTL 口径）⇒ **51 只 = 1 个请求**（每批 60）；失败返回 `{}` |
| `api/kpl._update_spot_change`（竞价异动现涨） | 先点查，**点查为空才退回全市场**（回退路径保留） |
| `api/stats._apply_change_stats`（三时点现涨 ~51 只） | 同上 |
| `kpl._boom_from_snap` / `_boom_spot_map(codes=None)` | **先过滤、再按存活代码取现涨**（过滤只用快照字段，与现涨无关，故安全）；不传 codes 时保留全市场旧行为 |
| 附带收益 | `ulist` 路径**不受 clist 熔断开关影响** ⇒ 东财 clist 熔断窗口里现涨仍有独立来源 |
