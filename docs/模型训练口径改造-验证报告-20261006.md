## 四、发布前必须解决的问题：概率尺度不同

| | 新模型 | 线上旧模型 |
|---|---|---|
| 09-30 首票概率 | **0.478** | 0.845 |
| 09-30 第 15 位概率 | 0.173 | 0.877 |
| top3 平均概率 | ≈0.40 | ≈0.90 |
| top3 **实际**命中率 | 40.85% | 28.91% |

- **新模型的概率是"诚实"的**：概率 0.40 对应实际命中 40.85%，几乎吻合。
- **旧模型的概率严重虚高**：报 0.90，实际只有 28.91%。

而线上评分体系 `backend/app/services/scorer.py` 的 `ai_buckets` 是**按旧模型虚高的尺度设计的**：

```python
"ai_buckets": [["0.90", "1.01", 1.0], ["0.85", "0.90", 0.85], ["0.80", "0.85", 0.70]]
#              概率≥0.90 → 满分 1.0；0.85~0.90 → 0.85；0.80~0.85 → 0.70
```

⇒ 直接换模型，**所有票的 ai 因子都拿不到分**，评分大幅下降，会被 `scoreFloor=50` 整体剔除。**只换模型文件不行，必须同步重定评分桶**（按真实命中率定桶，而非沿用虚高尺度）。

## 附二：因子集对比实验（8 月底 6 因子 vs 现在 11 因子）

**起因**：主人要求查看 8 月底 XGB 训练时的因子，判断是否该回去用更简单的因子集。

**8 月底（git 8/31 入库版）的 6 个因子**：

```python
FEATURES = ["bid_change", "bid_amount", "bid_turnover", "circ_mv", "yesterday_chg", "price"]
```

**推进到今天的路线**：
- 9/25 删 `yesterday_chg` → 5 因子。原因：线上链路该列实为**当日竞价涨幅**（9:25 已撮合出开盘价），训练基座是**前一交易日涨幅**，同名不同义。
- 10/02 `circ_mv` 原始值换成分位派生（`mv_rank`/`amt_rank`/`rank_diff`/`price_inv`）+ 补昨日侧三列 → 11 因子。

**实验设置**：同一候选池口径、同一 80/20 时序切分、同一超参（仅因子集不同）。

| 模型 | 测试集 AUC | 特征重要性前三 |
|---|---|---|
| **6 因子** | **0.7706** | bid_change 0.297 / bid_turnover 0.197 / yesterday_chg 0.142 |
| 11 因子 | 0.7106 | bid_change / yday_zt / bid_turnover |

**120 个交易日实战**（同一候选池、同一评估口径）：

| 评估口径 | 6 因子 | 11 因子 | 线上旧模型 |
|---|---|---|---|
| 全市场取前 30 | 29.86% | **30.00%** | 26.07% |
| 池内 top3 | **42.11%** | **42.11%** | 29.24% |
| 池内 top5 | **36.84%** | 35.61% | 26.14% |
| 池内 top10 | 29.12% | **30.18%** | 20.53% |

**结论：AUC 相差 6 个百分点，实战命中率却几乎完全相同。**

- top3 完全一致（都是 42.11%），其余档位互有胜负，差距都在 1.2pp 以内、不显著。
- 原因：**AUC 衡量的是全部样本的排序质量，而名单只吃榜头 top3~top10**。6 因子多出来的那部分 AUC 体现在中后段样本的排序上——而那部分根本不会出现在名单里。

**⇒ 不应为了"更高的 AUC"去恢复被删的因子。** 其中 `yesterday_chg` 上线还有硬伤：线上该列取值是**当日竞价涨幅**（与 `bid_change` 同信息），训练基座是前一交易日涨幅，同名不同义，直接上线必然 train-serve skew。

**⇒ 副产品结论：选因子不能用 AUC 当判据，要用 topN 命中率。** 这也解释了 10/02 那次改因子为何用"top3 命中 72.9% → 75.7%"作依据，而不是用 AUC。

（附带发现：8 月底的模型文件已被后续训练覆盖，服务器上只余 `models/_deprecated/model_xgb_v2.json`（9/25 的 v2），8 月底的模型本身不复存在；因子定义是从 git `5033666`「同步线上 8/31 最新版模型脚本入库」中取出的。）

## 附三：ai_buckets 定档实测 —— 并修正一个我自己下的错误结论

### 先修正：我上一版报告说"新模型概率够不着 0.80，ai_buckets 全部落空"，**这是错的**

那是拿 **2026-09-30 单日**数据测出来的，而 09-30 恰好是一个**特征缺失日**（见下）。剔除缺陷日后重测（58 个有效交易日）：

**新模型 top30 内部概率分位（每日中位数）**
```
min=0.795  P10=0.805  P25=0.823  P50=0.866  P75=0.900  P90=0.920
旧模型 top30 最低概率（对照）= 0.935
```
新模型与旧模型的概率尺度**是接近的**（榜内 0.80~0.92 vs 0.93~0.99）。

**原表（0.90 / 0.85 / 0.80）对新模型的实际效果**：

| 档位 | 拿到分的只数（满分 30） |
|---|---|
| ≥0.90 → 1.0 | 7.5 只 |
| 0.85~0.90 → 0.85 | 10.5 只 |
| 0.80~0.85 → 0.70 | 9.5 只 |
| <0.80 → 走中性 0.35 | **仅 2.5 只** |

⇒ **原表基本可用，只有 2.5/30 落空**，不是"全部失灵"。我之前的判断偏差，源于用了一天缺陷数据。

### 推荐的定档（按 top30 内部等分，零落空）

```python
"ai_buckets": [["0.900", "1.01", 1.0], ["0.823", "0.900", 0.85], ["0.700", "0.823", 0.70]]
```

效果：30 只里 7.5 只拿 1.0、15 只拿 0.85、7.5 只拿 0.70，**落空 0 只**。相比原表，主要是把第二档下限从 0.85 下移到 0.823、第三档下限从 0.80 下移到 0.70，使榜内票普遍能拿到分，不再有票被当成"普通票"。

### 🔴 但真正的缺陷在这里：涨停标签未回填，导致"昨日侧"特征全为 0

剔除缺陷日时暴露出来的：

```
2026-09-23   yday_zt 有值  prev_mkt_zt 有值    ← 正常
2026-09-24   全行 is_limit_up = NULL（标签 0 行）   ← 根因
2026-09-28   yday_zt=0  prev_mkt_zt=0        ← 被污染（它依赖 09-25 的标签）
2026-09-29   全行 is_limit_up = NULL（标签 0 行）   ← 根因
2026-09-30   yday_zt=0  prev_mkt_zt=0        ← 被污染（它依赖 09-29 的标签）
```

`yday_zt` / `yday_lb` / `prev_mkt_zt` 这三个"昨日侧"特征是**从上一个交易日的涨停标签算出来的**（见 `db.attach_derived`）。上游标签缺失，它们就全为 0。

后果：模型在 09-28 / 09-30 两天的输出**整体塌陷**——

```
正常日   新模型 top30 概率 0.795 ~ 0.920
09-28    新模型 top30 概率 0.313 ~ 0.694
09-30    新模型 top30 概率 0.306 ~ 0.695
```

也就是说这两天模型是在"少了一半信息"的情况下打分的，概率普遍打到 0.80 以下 ⇒ **那两天 AI 因子确实会大面积落空**——但这不是模型的问题，是输入数据的问题。

**范围统计**：全表 368 个交易日中有 **237 天**存在"昨日侧全 0"（集中在更早期，多为历史回填段）；而**训练池实际使用的 132 天里有 3 天**（占 2.3%，对训练影响可控）。近期的频率不低：最近 5 个交易日里就有 2 天被污染。

**建议**：发布前先确认涨停标签回填任务（`collector.py --label`，15:04）是否正常跑；并加一条巡检——"当日 `prev_mkt_zt` 是否全为 0"，若为 0 则说明上游标签缺失、当日 AI 分数不可信。**这件事比调 ai_buckets 的阈值重要得多**：阈值只影响 2.5 只票拿不拿到分，标签缺失会让整天 30 只票的分数全部失真。

## 附四：训练口径最终版（训练不设限）· 以及评估基准的修正

### 主人的最终口径

**训练时只要求「40 个交易日内有过涨停」这一条**；竞价涨幅 / 竞价成交金额 / 流通市值 **训练时都不限制，只在展示时（预测侧）筛**。

道理：训练要让模型看到**全市场的特征分布**。若把"涨幅≤7%、市值≤200亿"塞进训练池，模型只见过池子里那批票，学到的只是池内相对排序；一旦展示侧口径微调（例如金额门槛从 3000 万挪到 5000 万），模型输入分布就整体漂到训练分布之外。

### 连带修掉一个 bug：筛选顺序

`_select_training_frame` 判定"真实采集段"的判据是**单日行数 > 3000**。池子筛选会把这行数砍到几百 ⇒ 判据必然误判成"没有真实采集段"，模型于是回退到"全量（含回补近似数据）"。

改为**先判数据来源、再筛涨停基因**后，判据恢复正常，并带来一个意外收获——它真正剔除了回补近似数据：

```
加载数据: 261,313 行 / 132 天（2026-03-18 ~ 2026-09-30）
  真实采集段 184,312 行 / 34 天（单日 >3000 行）      ← 只有 34 天！
  → 采用仅真实采集段（回补近似数据不参与训练）
  训练池: 184,312 行 → 40 交易日内有过涨停 30,642 行（涨停率 4.00%）
  训练集 22,228 行（2026-08-10~09-16） / 测试集 8,235 行（09-17~09-30）
```

### 训练结果

| 模型 | 测试集 AUC |
|---|---|
| XGBoost | 0.7546 |
| LightGBM | 0.7564 |

（此前那版 0.7106 是在"含回补段"的混合数据上算的，两者不可比。）

### 🔴 评估基准的修正：必须用真实采集段

同一批模型在三个窗口下评估，**结论方向完全相反**：

| 窗口 | 6因子(8月底版) | 11因子(新训) | 线上旧模型 |
|---|---|---|---|
| **34 天（纯真实采集段）** | 41.37% | **49.96%** | 46.03% |
| 60 天 | 33.17% | 30.87% | 32.86% |
| 120 天 | 29.86% | **19.49%** | 26.07% |

（口径=全市场取概率前 30；池内 topN 同向）

原因：新模型**只在真实采集段（8/10 之后）训练过**，更早的 98 天是 backfill 的近似数据（`竞价额 ≈ 开盘价 × 量 × 0.15`，是编出来的）。拿回补段数据评估它，等于拿它没见过的数据考它，必然失真。

**线上实际收到的就是真实采集分布** ⇒ **34 天窗口才是正确基准**。在这个基准上（池内口径）：

| 口径 | 新模型 | 线上旧模型 |
|---|---|---|
| 全市场 top30 | **49.96%** | 46.03% |
| 池内 top3 | **39.29%** | 39.29% |
| 池内 top5 | **42.14%** | 35.00% |
| 池内 top10 | **33.93%** | 28.57% |

### 当前数据瓶颈（如实记录）

- **真实采集数据只有 34 天**（2026-08-10 ~ 2026-09-30），这是模型样本量的硬上限。
- 更早的 98 天是回补近似数据，特征是"编"的，不能用于训练（实测：混入后模型在真实分布上的表现反而变差）。
- 随真实数据每天累积（+5,000 行/天），模型会持续变好——**这是提升模型的正路，比调因子、调阈值都管用**。

## 附六：涨停标签缺失 —— 根因链与修复（2026-10-06 已修）

### 现象

09-28、09-30 两天模型输出塌陷（概率 0.31~0.70，正常日 0.80~0.96）。

### 根因链（逐环）

4. `yday_zt` / `yday_lb` / `prev_mkt_zt` 这三个"昨日侧"特征由 `db.attach_derived` 在**采集当时**从上一个交易日的标签算出 ⇒ 上游缺标签 ⇒ 09-28、09-30 的昨日侧全为 0。
5. 昨日侧是模型 11 个输入特征中的 3 个 ⇒ 模型在这两天等于**少了一半信息** ⇒ 概率整体塌陷。

```
collector.py --label --date 2026-09-29  → 回填 5,559 条（涨停 57 只）
```
（猫爪现在能取到这两天数据，说明当时是时序/降级失败，可补。）

**② 重算派生列**（对 09-28、09-30 调 `db.attach_derived` 并回写三列）

| 日期 | sum(yday_zt) 改前 → 改后 | sum(prev_mkt_zt) 改前 → 改后 |

| 2026-09-28 | 0 → **52**（= 09-24 涨停家数） | 0 → 289,172 |
| 2026-09-30 | 0 → **57**（= 09-29 涨停家数） | 0 → 337,611 |

### 附十三：机会清单「综合评分」的依据（主人 2026-10-06 问）

**不是概率，是"当日候选池内的排名百分位"**。链路（`chaozhi.py` 的 `fuse()`）：

```
predictions_<date>.json      (金睛/xgb, top ≤30) ─┐
output/lgb/predictions_*.json(火眼/lgb, top ≤30) ─┴→ 合并去重 → 剔除越界票 → 候选池
                                                            ↓
                        金睛/火眼列 = ai_prob × 100（模型原始输出，**未校准**，仅供排序）
                                                            ↓
                        池内各自排名 → rankXgb / rankLgb（百分位 0~1，最高分=1.0）
                                                            ↓
              综合评分 = 100 × (0.5 × rankXgb + 0.5 × rankLgb)   ← 等权，权重可热改
                        分歧度 = |rankXgb − rankLgb|
                                                            ↓
                        标签 = f(综合分, 分歧度, 风险)  ← 关注/观察/谨慎/待定
```

**关键：只看排名，不看分数本身。** 用 09-30 九阳股份例（后端函数实跑复现）：

```
金睛 98 分、火眼 96 分（abs 分）→ 池内 15 只中两模型都排第 1
rankXgb=0.9286、rankLgb=0.9412 → 综合 = 100×(0.9286+0.9412)/2 = 93.49 → 93
（不是 (98+96)/2 = 97 —— 两模型分数尺度不一定可比，排名更稳健）
```

09-30 全池复现（与页面逐行一致）：

```
序  名称      金睛 火眼 | 金睛rank 火眼rank | 综合 分歧   标签
1   九阳股份   98   96  |  0.9286   0.9412  |  93  0.0126 关注
2   善水科技   98   96  |  0.9286   0.9412  |  93  0.0126 观察
3   华之杰    98   96  |  0.9286   0.9412  |  93  0.0126 关注
4   新华传媒   93   93  |  0.75     0.7353  |  74  0.0147 观察
...
13  会稽山    69   74  |  0.2143   0.2941  |  25  0.0798 谨慎
```

⚠️ **使用注意**：① 百分位是**池内相对值** ⇒ 池子大小/构成变了分数就变，**跨交易日不可直接比**，同日内可比；② 金睛/火眼两列是**未校准**的模型原始输出，**不能当概率读**（表头/单元格已注明"仅用于排序"）；③ 池子之所以在池内算而非全市场，是因为实测在全市场 5500 只里算百分位时前 60 名会全挤在 99~100，失去区分度。

### 附十四：单模型排名是否吃亏 + 三项交互改动（2026-10-06 深夜）

**① "只有 1 个排名的票会不会吃亏"——不会，算法按可用权重归一**

`fuse()` 是 `num/den` 结构（分子分母都只累加**存在的模型**）：

```python
num = (w1*a if a is not None else 0) + (w2*b if b is not None else 0)
den = (w1 if a is not None else 0) + (w2 if b is not None else 0)
scoreFused = 100 * num / den
```

⇒ 单模型票的 `den` 只有 0.5 ⇒ **综合分恰等于该模型 rank × 100**，与"该模型单独排名"完全等价。
实测 09-30 N鸿富诚（金睛缺失）：火眼 rank 0.4118 → 综合 **41** = 0.4118×100，**没有被 0 稀释**。

⚠️ 但需**纠正一处误读**：主人点名"只有 1 个排名的上海洗霸"——**上海洗霸两个排名都有**（金睛 rank 0.2857 + 火眼 rank 0.5 → 综合 39）。它分低不是"缺模型"，而是**排名本身靠后**（金睛 73 分在池内偏后；火眼 83 分只排中间）。真正单排名的例子是 N鸿富诚。

**两个"轻微不理想"（真实存在，是否调整待主人定）**：

- **并列顶端不满分**：`_pct_rank` 用"平均名次"，三只并列最高分（98）时 rank 只有 0.9286 ⇒ 综合 93 而非 100。对所有并列者一视同仁，不是排序错误。
- **两模型 top 数量不同**（金睛 21 vs 火眼 30）⇒ 两池大小不同，rank 的"含金量"略有差异（金睛入选门槛更高）。

**② 表头与数据同对齐（居中）**：基础规则 `.czh-table th` / `td` 均改为 `text-align: center`（口径同 AI 精选报告 `.ap-stock-table`：整表居中，含名称列与概念列）；此前只有部分列居中、`th` 还是 `left`。

**③ 表头可点击排序**：结构照 `AipickReport.vue`（`sortKey/sortDir/sortVal/sortCompare/toggleSort/thCls`）——数值列首点降序、文本列首点升序、空值恒排末尾、**高亮反馈不用箭头**（2026-09-05 主人明确"所有表格去掉排序箭头"）。`#` 列点击恢复后端默认序（综合评分降序）。

⚠️ 实现时**打破了一个循环依赖**：`realtime` 排序键经 `sortVal→rtVal` 依赖 `quotes`，而 `quotes` 由 `loadRealtime` 写入、原 `watch(shownPicks)` 触发 ⇒ `shownPicks→quotes→shownPicks` 会无限打圈。改为 `loadRealtime` 取码读 `picks`（不再依赖 `shownPicks`）+ `watch(picks)`。

**④ 手机端横向滑动**：新增 `.czh-table-scroll { overflow-x: auto; -webkit-overflow-scrolling: touch }`（**无条件**开启，照 AipickReport 教训：只在窄屏开会让 769~900px 区间没兜底）+ 窄屏 `min-width: 720px`（各列定宽之和 718）+ 横滑提示 `.czh-swipe-hint`（仅窄屏显示）。≤480px 处因收起 2 列，地板降为 620。

### 附十五：综合分该"按排名"还是"按模型分数"算（主人 2026-10-06 问）

**现状 = 按排名**（`fuse()` 取池内百分位加权）。以下是两种方案的实测对比与判据。

**① 决定性证据：两个模型的分数**不在同一把尺子上

```
同一个分数 → 在该模型 top 名单内的分位：
  分数     金睛内分位    火眼内分位    差
  70       21.1%       10.8%     10.3pp
  75       32.2%       20.0%     12.2pp
  80       44.4%       32.5%     11.9pp
  90       66.7%       65.8%      0.9pp
  95       78.9%       90.8%    -11.9pp
```

同一个 80 分，在金睛里是"垫底 44%"、在火眼里只是"垫底 32%" ⇒ **直接平均会让给分更慷慨的那个模型主导结果**。
两个模型都**未做概率校准**（`ai_prob` 就是原始输出），所以"绝对分数"在方案 B 里本就没有可比性。

**② 但两种方案的实际名单差异很小**（09-30 实测，池内 30 只）

```
两方案 top3 完全一致：九阳股份 / 善水科技 / 华之杰
分歧最大的几只（A名次 vs B名次）：中新赛克 22↔25、津药药业 21↔24、新华传媒 4↔5
```

⇒ 这不是"对与错"，而是"哪个更稳"。两模型基于同一天同一批特征、分数高度相关，所以排序大体一致，分歧集中在中低段。

**③ 判据：按排名更稳（决定性理由 = 抗模型换版）**

| | A 按排名（现状） | B 按分数 |
|---|---|---|
| 尺度可比性 | ✅ 都归一成 0~1 分位 | ❌ 两模型分布不同（见上表） |
| **模型换版后** | ✅ **不受影响** | ❌ **整体崩**：新模型概率区间从 0.9 量级降到 0.5 量级，分数全部缩水 |
| 抗异常值 | ✅ 单个高分不改变位置 | ❌ 被单模型高分绑架 |
| 绝对水平 | ❌ 丢失（池内全弱时第一名也满分） | ✅ 保留 |
| 跨日可比 | ❌ 不可比（池子/构成变则变） | ❌ 也不可比（未校准） |

⇒ **结论：保持按排名**。B 唯一优于 A 的地方是"保留绝对水平"，但**前提是先做概率校准**（把两模型分数映射到统一尺度）——测试机已有 `calibrate.py`、**生产上并没有**，所以现在切 B 只会更差。
