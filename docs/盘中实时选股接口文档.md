> **版本**：对应线上 `v4.11.79`（两台机器均已部署）
> **撰写依据**：源码逐行核对 + **生产机实测**（2026-09-28 15:0x，见文末「实测附录」）

## 一、接口总览

| 项 | 值 |
|---|---|
| **端点** | `GET /api/stocks_spot` |
| **协议** | HTTPS（生产 nginx 强制跳转，`http://` 会 301） |
| **鉴权** | **必须**。`Authorization: Bearer <token>` 或 `?token=<token>` |
| **成功响应头** | `Cache-Control: no-store` |
| **返回体** | JSON（`Content-Type: application/json`） |
| **是否落库** | ❌ 不落批次、不推送、不参与 9:25 定格 —— 每次请求都是**当下重算** |
| **是否有 9:26 闸门** | ❌ **无**。盘中随时可调（这是与竞价 `/api/stocks` 最本质的区别） |

### 为什么是独立端点，而不是 `/api/stocks?strategy=spot`

这是历史上真实踩过的坑，**接接口前必须知道**：

- 原 `spot` 策略挂在 `/api/stocks?strategy=spot`，2026-09-09 随提交 `4c56083` **整体下线**（前端无入口 + 后端显式 400）。
- 2026-09-28 重建时**没有**复活那个 strategy 参数，而是**新开独立端点**。原因：`/api/stocks` 已长到 71K，内含 `pick_window_guard`（9:00~9:26 闸门）、当日幂等、直读批次、冻结字段等**一整套只对竞价成立的逻辑**。塞回同一路由会：
  1. 每个分支都要重判「这逻辑对 spot 适用吗」—— 极易漏判；
  2. 动大文件的缩进/行尾风险高。
- 独立端点 = 独立语义 + 独立可回滚（**不挂载 `include_router` 即下线**）。
- ⚠️ 因此 **`/api/stocks?strategy=spot` 现在返回 400**，不要再用。前端的 `fetchStocksSpot()` 走的就是独立端点。

## 二、请求参数

### 2.1 `action`（唯一必填语义参数）

| 值 | 含义 | 说明 |
|---|---|---|
| `filter` | **盘中实时出名单**（默认） | 不传 `action` 时默认走它 |
| `ping` | 探测可用性 | 只回 `{ok, strategy, available}`，**不受交易时段限制**，不查行情、不耗资源 |

其他值 → **HTTP 400**，响应 `{"ok": false, "msg": "非法参数(仅支持 filter/ping)"}`。

### 2.2 筛选参数（`action=filter` 时生效）

全部为**可选**，不传走默认值。参数经 `scorer.validate_filters()` **钳位（clamp）** 处理：
超出上下限**不会报错**，而是被夹到边界值；非法字符串则回落默认值。

| 参数 | 类型 | 默认 | 钳位范围 | 作用 |
|---|---|---|---|---|
| `markets` | 逗号分隔 | `hs,cyb,kcb` | 白名单过滤 | 市场范围。`hs`=沪主板 60x/601/603/605 + 深主板 000/001/002/003；`cyb`=300/301；`kcb`=688/689。**北交所一律排除**（不认 `bj`） |
| `stSuspend` | 0/1 | `1` | — | `1`=**保留** ST 与停牌股；`0`=剔除 ST 与停牌股 |
| `limitUp` | 0/1 | `1` | — | `1`=**包含**昨涨停/连板股；`0`=剔除 |
| `chgFloor` | float | `0` | -20 ~ 30 | **实时涨幅下限**（%） |
| `chgGt` | float | `9.5` | -20 ~ 30 | **实时涨幅上限**（%）。`0` 或负值意味着「不设上限」不会被触发（判定条件是 `>0`） |
| `volRatioFloor` | float | `1` | 0 ~ 20 | **量比下限**。`0`=门槛关闭 |
| `turnoverFloor` | float | `1` | 0 ~ 100 | 换手率下限（%）。`0`=关闭 |
| `turnoverGt` | float | `0` | 0 ~ 100 | 换手率上限（%）。`0`=不限 |
| `spotExcludeZT` | 0/1 | `0` | — | `1`=剔除**已涨停封板**的票（买不进） |
| `scoreFloor` | float | `50` | **50 ~ 100** | **单阈值硬门槛**，评分低于此值直接不入选。⚠️ 钳位下限是 **50**，`0` 已不可用于关闭门槛 |
| `probLt` | float | `50` | 5 ~ 95 | 概率下限（**双低**判定：与 `confLt` 同时不满足才剔除） |
| `confLt` | float | `50` | 50 ~ 90 | 置信度下限（同上，双低才剔除） |
| `floatMvFloor` | float | `30` | 0 ~ 5000 | 市值下限（**亿**，口径 = 自由流通市值优先） |
| `floatMvGt` | float | `100` | 0 ~ 5000 | 市值上限（亿），`0`=不限 |
| `priceGt` | float | `30` | 0 ~ 5000 | **价格**上限（元），用**实时价**判定 |

#### ⚠️ 明确「不消费」的竞价参数（传了也无效）

以下是竞价链路的参数，`spot` **有意不消费**：

| 参数 | 为什么不用 |
|---|---|
| `bidGt` / `bidLt` | 竞价涨幅区间 —— 盘中看的是**实时**涨幅（`chgFloor`/`chgGt`） |
| `bidAmtFloor` | 竞价额门槛 —— 盘中距 9:25 已远，竞价额不是选股依据（老实现同样不含） |
| `probLt` 的单用 | spot 里它与 `confLt` 是**双低**关系，不是单独硬门槛 |

> 这 6 个盘中参数（`chgGt`/`chgFloor`/`volRatioFloor`/`turnoverFloor`/`turnoverGt`/`spotExcludeZT`）
> 在 2026-09-09 spot 下线后曾一度**零消费点** —— 即前端能勾、选了不生效的静默失效期。
> 2026-09-28 重建后已全部接回。

## 三、响应结构

### 3.1 `action=ping`

```json
{ "ok": true, "strategy": "spot", "available": true }
```

### 3.2 `action=filter` 成功

```json
{
  "ok": true,
  "strategy": "spot",
  "mode": "spot",
  "list": [ /* 见 3.3 */ ],
  "count": 133,
  "before930": false,
  "dataTime": 1759043345,
  "degraded": false,
  "stats": { "chg_floor": 4245, "vol_ratio": 416, "...": 0 }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 成功为 `true` |
| `strategy` / `mode` | str | 恒为 `"spot"`，便于前端分流 |
| `list` | array | 入选股票列表，**已按概率降序 + code 升序**排好 |
| `count` | int | 入选数量 = `len(list)` |
| `before930` | bool | 今日 9:30 前为 `true`。由 `scorer.bj_now()` 按**北京时间**判定 |
| `dataTime` | int | 服务端 Unix 时间戳（秒） |
| `degraded` | bool | 顶层恒为 `false`；**单票**的降级标记看 item 里的 `degraded` |
| `stats` | object | **逐条剔除原因计数**（可观测性设计，见 3.4） |

### 3.3 `list` 元素字段（22 个键，生产实测全量）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `code` | str | — | 6 位股票代码 |
| `name` | str | — | 股票名称 |
| `probability` | int | 分 | **评分概率**（5 ~ 95 钳位） |
| `confidence` | int | 分 | **置信度**（55 ~ 90 钳位） |
| `realChange` | float\|null | % | **实时涨幅**（核心因子 1） |
| `entityChange` | float\|null | % | 实体涨幅（现价相对开盘） |
| `volRatio` | float\|null | 倍 | **量比**（核心因子 2） |
| `turnover` | float\|null | % | **换手率**（核心因子 3） |
| `sealRatio` | float | % | **封成比** = 封单额 / 自由流通市值 ×100（因子 4） |
| `sealFund` | float | 亿 | 封单额 |
| `limitBoards` | int | 板 | 连板数（来自涨停池，非涨停为 0） |
| `breakCount` | int | 次 | 开板次数（来自涨停池） |
| `circulationMV` | float\|null | 亿 | 流通市值（四舍五入 4 位） |
| `freeCirculationMV` | float\|null | 亿 | 自由流通市值。⚠️ 可能为 `null` |
| `price` | float\|null | 元 | 现价 |
| `amount` | float\|null | 亿 | 成交额（内部为元，下发除以 1e8） |
| `bidChange` | float\|null | % | **竞价涨幅**（读当日 9:25 定格快照 `snapshot_bid`） |
| `bidAmt` | float\|null | **万元** | **竞价额**（读 9:25 定格，下发再 /1e4 折回万元） |
| `industry` | str | — | 行业，无则 `"-"` |
| `concept` | str | — | 概念串（逗号分隔），无则 `"-"` |
| `source` | str | — | 行情来源，如 `"eastmoney"` |
| `degraded` | bool | — | 该行是否为降级数据 |

**缺失值语义**：一律 `null`，**绝不填 0**（契约铁律）。前端展示时应渲染为 `-`。

#### 🔴 `bidChange` / `bidAmt` 的取值链路（v4.11.78 修复记录）

这两个字段曾**恒为 `null`**（「键下发了 ≠ 值有内容」的典型事故）。根因：`QuoteRow.from_eastmoney(auction_window=False)` 的竞价字段有三条来源 —— 定格 map 优先 → 窗口内实时 `f615/f616` → 否则 `None`。而 spot 侧**只传了 `auction_window=False`，没传定格 map**，前两条都不成立 ⇒ 恒 `None`。

**现修法**：读当日 9:25 定格快照
- `auction_snapshot.load_day_bid_change()` → `{code: 竞涨%}`
- `auction_snapshot.load_day_bid_amt()` → `{code: 竞价额(万元)}`

这两个 loader **自带非交易时段回退最近交易日**，故盘前/周末/节假日调用也能拿到「最近一次竞价」的值，不会又变回 `null`。

> ⚠️ 这两个字段**只是展示字段，不参与 spot 六因子评分**。读取失败一律降级为 `{}` ⇒ 那两列显示 `-`，**绝不阻塞选股主流程**。

### 3.4 `stats` 剔除原因字典

每一只被剔除的票都会**按原因计数**，便于排查「为什么这只票没进名单」。

| key | 含义 |
|---|---|
| `market` | 市场范围不符（北交所、或不在 `markets` 内） |
| `first_board` | `limitUp=0` 且命中昨涨停/连板 |
| `st` | `stSuspend=0` 且名称含 `ST` |
| `suspend` | 判定为停牌 |
| `suspend_unknown` | 停牌状态未知且 `drop_unknown_suspend`（spot 侧默认 `False`，一般不出现） |
| `spot_zt` | `spotExcludeZT=1` 且已涨停封板 |
| `no_real_change` | **实时涨幅缺失**（该票拿不到实时数据） |
| `chg_floor` | 实时涨幅 < `chgFloor` |
| `chg_gt` | 实时涨幅 > `chgGt` |
| `vol_ratio` | 量比缺失或 < `volRatioFloor` |
| `turnover_floor` | 换手率缺失或 < `turnoverFloor` |
| `turnover_gt` | 换手率 > `turnoverGt` |
| `prob_conf` | 概率与置信度**双低** |
| `score_floor` | 评分 < `scoreFloor` |
| `mv_floor` | 市值缺失或 < `floatMvFloor` |
| `mv_gt` | 市值 > `floatMvGt` |
| `price_gt` | 实时价 > `priceGt` |

**剔除顺序**（先便宜后昂贵，与老实现逐条对齐，便于对拍）：
`market → first_board → st/suspend → spot_zt → chgFloor/chgGt → volRatioFloor → turnoverFloor/turnoverGt → prob_conf → score_floor → mv_floor/mv_gt → price_gt`

### 3.5 错误响应

| 场景 | HTTP | 响应体 |
|---|---|---|
| 未登录 / token 失效 | **401** | `{"detail":{"ok":false,"code":"expired","msg":"未登录或登录已过期"}}` |
| 被其他设备顶出 | **401** | `{"detail":{"ok":false,"code":"kicked","msg":"账号已在另一设备登录，本设备已退出"}}` |
| 账号过期（非管理员） | **403** | `{"detail":{"ok":false,"msg":"账号已过期，请联系管理员续费"}}` |
| `action` 非法 | **400** | `{"ok":false,"msg":"非法参数(仅支持 filter/ping)"}` |

## 四、六因子评分口径

来源：`app/services/picker/score_spot.py` 的 `DEFAULT_SCORING_SPOT`。

### 4.1 权重

| 因子 | 权重 | 数据来源 |
|---|---|---|
| 实时涨幅 `chg` | **0.28** | `row.real_change` |
| 量比 `vol_ratio` | **0.26** | `row.vol_ratio` |
| 换手率 `turnover` | **0.18** | `row.turnover` |
| 封单强度 `seal`（封成比） | **0.14** | 涨停池 `fund` / 自由流通市值 |
| 流通市值 `market` | **0.08** | `row.mv_yi`（自由流通优先） |
| 昨日涨幅 `yesterday` | **0.06** | `row.yesterday_change` |

`probability = clamp(Σ(因子分 × 权重) × 100, 5, 95)` → 四舍五入为整数

### 4.2 各因子分档表

| 因子 | 分档（区间 → 得分） | 缺失默认分 |
|---|---|---|
| **实时涨幅** (%) | 3~6 → 1.0｜1.5~3 → 0.85｜6~9.5 → 0.85｜0~1.5 → 0.5｜9.5~99 → 0.35｜-99~0 → 0.15 | **0.1** |
| **量比** (倍) | 2~99 → 1.0｜1.5~2 → 0.85｜1~1.5 → 0.6｜0.5~1 → 0.35 | **0.15** |
| **换手率** (%) | 3~15 → 1.0｜1.5~3 → 0.8｜15~25 → 0.7｜0.5~1.5 → 0.45｜25~99 → 0.35 | **0.15** |
| **封成比** (%) | 2~99 → 1.0｜1~2 → 0.85｜0.5~1 → 0.65｜0.1~0.5 → 0.4 | **0.12** |
| **流通市值** (亿) | 0~30 → 1.0｜30~60 → 0.88｜60~120 → 0.68｜120~250 → 0.45 | **0.22** |
| **昨日涨幅** (%) | 3~9.5 → 0.9｜9.5~99 → 0.65｜1~3 → 0.65｜0~1 → 0.4｜-3~0 → 0.25 | **0.15** |

**设计意图**：实时涨幅的**最优区间是 3%~6%**（健康上涨），超过 9.5% 只给 0.35（追高风险）；市值越小分越高（0~30 亿满分）；封单强度只对涨停股有效。

### 4.3 置信度（三项加成，基准 65）

| 条件 | 加成 |
|---|---|
| 封成比 ≥ 2% | **+12** |
| 量比 ≥ 2 | **+8** |
| 1.5% ≤ 实时涨幅 ≤ 6% | **+6** |

`confidence = clamp(65 + Σ加成, 55, 90)`

> **缺失值一律不加成**（不是加 0 分档）。基准 65 起步，最多 91 → 钳到 90。

### 4.4 与竞价的本质区别

| | 竞价（`/api/stocks`） | 盘中实时（`/api/stocks_spot`） |
|---|---|---|
| 看的数据 | **9:25 定格**（全天恒定） | **实时**（每次调用都在变） |
| 因子数 | 5 | **6**（多了封单强度） |
| 涨幅因子 | 竞价涨幅 `bid_change` | **实时涨幅** `real_change` |
| 时间闸门 | 有（`pick_window_guard`，9:00~9:26） | **无** |
| 9:26 定格 | 参与 | **不参与** |
| 落批次/推送 | 是 | **否** |
| 前端本地预筛 | 可以（定格值恒定） | **不可以**（实时值每次都变） |

### 4.5 评分权重可被管理端覆盖

配置存 `settings` 表，key = **`scoring_spot`**。

- 合并策略与竞价侧 `scorer.get_scoring_cfg` **逐条同构**：
  - 数值键（`w_*` / `conf_*`）：白名单校验 + `float` 转型，非法值**静默跳过**（沿用默认）；
  - `factors`：**逐层合并**（缺的因子/键取默认），**不做整表替换** —— 防止旧配置缺了新因子后整块默认分档丢失。
- **内存缓存**：`compute_score_spot` 每只票调一次，一场选股调几百次，故缓存。管理端保存后调 `reload_spot_cfg()` 强制失效（与竞价侧 `reload_scoring_cfg` 对称）。
- ⚠️ 与竞价侧是**独立缓存**，不共用 —— 两者因子表不同（5 vs 6），键名部分重合但语义分档不同，共用必然串味。

```python
import requests

BASE = "https://{BASE}"
TOKEN = "..."

r = requests.get(f"{BASE}/api/stocks_spot",

```

## 六、性能与实测表现

生产实测（`v4.11.79`，默认参数，2026-09-28 15:0x）：

- 全市场扫描 → **入选 133 只**，耗时 **约 1.x 秒**（日志会打 `spot 选股 uid=x 全市场N→入选M 剔除={...} 耗时Xms`）
- `stats` 实测分布（可见「实时涨幅下限」是主要筛除项）：
  `chg_floor 4245`｜`vol_ratio 416`｜`no_real_change 350`｜`mv_floor 119`｜`turnover_floor 121`｜`mv_gt 62`｜`score_floor 55`｜`chg_gt 40`｜`price_gt 19`｜`market 1`

**性能设计要点**：
1. 复用 `fetcher.ensure_spot_cache("refresh", fs, before930)` 拿全市场实时行情（**东财 diff 增量**，非全量拉取）；
2. 涨停池 `fetch_zt_pool()` **失败不阻塞** —— 降级为 `{}`，封单因子记 0 分；
3. 9:25 定格读取**失败不阻塞** —— 降级为 `{}`，`bidChange`/`bidAmt` 显示 `-`。

**降级是分层的**：任何一个可选数据源挂掉，都只影响它对应的字段/因子，**不会让整个接口失败**。

## 八、注意事项清单（接入前对照）

1. **业务失败是 HTTP 200** —— 必须判 `ok` 字段，不能只看状态码。
2. **无 9:26 闸门** —— 盘中随时可调，但也意味着**没有「定格」概念**，每次结果都可能不同。
3. **不要用 `/api/stocks?strategy=spot`** —— 已下线，返回 400。
4. **不消费竞价参数** —— `bidGt`/`bidLt`/`bidAmtFloor` 传了无效。
5. **参数越界不报错** —— 会被静默钳位到边界值（如 `scoreFloor=0` 会变成 `50`）。
6. **`scoreFloor` 无法关闭** —— 钳位下限 50（2026-09-20 起，50 分是系统铁底）。
7. **缺失值一律 `null`** —— 前端渲染为 `-`，不要当 0 用。
8. **`bidAmt` 单位是万元**，`amount` 单位是亿，`sealFund` 单位是亿。
9. **市值口径是自由流通市值** —— 2026-09-20 起统一（门槛与评分同口径，避免双口径名单漂移）。
10. **`spotExcludeZT` 依赖涨停池** —— 涨停池获取失败时该门槛不生效（不误杀，但也不剔除）。
11. **不做本地快照预筛** —— 实时值每次都变，本地缓存会导致名单与后端不一致。
12. **无缓存头** —— 响应带 `Cache-Control: no-store`，客户端也不要自行缓存。
