# 生产 `models/current.json` 里 `live: null` 的性质判定（2026-10-06）

> 主人问：`live: null` 是**有意**还是**异常**？
> 结论：**是有意设计，不是异常**。但它背后暴露了三件需要知晓的事。

---

## 一、先看现场

```json
// /opt/kuaixuan/aipick/models/current.json   （文件时间 2026-10-03 08:19:57）
{
  "live": null,
  "shadow": "v_live_start",
  "shadow_trained_at": "2026-10-03 08:19:57"
}
```

`versions/` 下的全部候选：

```
v20261003_0811   (10-03 08:11)
v20261003_0814   (10-03 08:14)
v_live_start     (10-03 08:15)
v_oos            (10-03 08:18)
v_oos_test       (10-03 08:14)
```

## 二、判定：**有意**，`null` 的语义就是"从未有版本通过闸门"

`live` 字段只在**两处**被赋值（`scripts/aipick/shadow.py`）：

```python
def cmd_promote(a):        # 晋级
    p['live_prev'] = p.get('live')
    p['live'] = ver                    # ← 只有通过闸门才会写
def cmd_rollback(a):       # 回滚
    p['live'], p['live_prev'] = prev, p.get('live')
```

而 `cmd_train`（训练影子候选）**只写 `shadow`，不碰 `live`**：

```python
ptr = _pointer()
ptr['shadow'] = run                    # 只改影子指针
ptr['shadow_trained_at'] = meta['trained_at']
_write_pointer(ptr)
```

⇒ **`live: null` = "没有任何版本通过闸门晋级过"**，语义完全正确。

### 为什么它一直没被赋值：**调度还没跑过**

影子系统的调度**存在**（`aipick_scheduler.py`）：

```
aipick_shadow        9:27   影子出名单 → pick_daily_shadow
aipick_shadow_train  19:15  训练影子候选 → models/versions/
aipick_shadow_gate   19:25  闸门判定（20日同日配对 ≥2pp 且 t≥1.0 且 top5 不劣）
```

但：

- `versions/` 里 5 个候选**全部集中在 10-03 早上 8 分钟内** ⇒ 是**人工调试产物**，不是调度产出
- 此后**没有新候选**
- `journalctl -u kx-worker` 里**没有任何 shadow/gate 执行记录**
- **原因**：影子系统 10-03 早上搭好，而 **10-03 起国庆休市** ⇒ 调度（按交易日执行）**从未触发过**

⇒ **`live: null` 是"系统还没开始跑"的初始状态**，不是故障。

---

## 三、但有三件事需要主人知晓

### ① ⚠️ 影子系统与主链路是**两套模型体系**，别混淆

| | 主链路（真正在跑）| 影子闸门系统 |
|---|---|---|
| 加载哪个模型 | **`model_xgb.json`**（`ai_predict.py`）| **`model_lgb.txt`**（`shadow.py` 的 `LIVE` 常量）|
| 影响面 | 评分 AI 因子、机会清单「金睛」列 | 火眼页、机会清单「火眼」列 |
| 谁在跑 | 9:27 预测 + 18:59 重训（每日）| 9:27 / 19:15 / 19:25（**尚未跑过**）|

**⚠️ `shadow.py:50` 的注释是错的**：

```python
LIVE = os.path.join(MODELS, 'model_lgb.txt')   # 线上加载路径（ai_predict.py 读它）
                                                 # ↑ 后半句错误：ai_predict.py 读的是 model_xgb.json
```

生产日志实证：`[AI预测] 模型已加载 /opt/kuaixuan/aipick/models/model_xgb.json (宽度 11)`

⇒ 注释会误导排障（以为影子系统管的是 AI 因子，实际管的是火眼链路）。**建议修正**。

### ② ⚠️ 开工后影子系统大概率会**卡住**，不会有任何产出

- **19:15 `train` 会被"冻结规则"跳过**（设计如此，防样本内）：
  ```python
  if not a.force:
      cur = _pointer().get('shadow')
      if cur:  return cur        # 只要存在影子指针就跳过重训
  ```
  当前 `shadow = v_live_start` 一直存在 ⇒ **每天都会跳过**

- **19:25 `gate` 的样本外（OOS）校验不通过**：
  ```python
  t_end = meta['train_range'][1]      # v_live_start: 2026-09-30
  if test[0] <= t_end:                # test[0] = 最近 20 日窗口起点 ≈ 09-10
      oos_ok = False                  # ⇒ 判为"样本内评估，禁止晋级"
  ```
  ⇒ 决策恒为 `continue_shadow`

⇒ **净结果：影子系统会永久停在 `v_live_start`**，既不出新候选、也不晋级。
（**不影响线上** —— 影子系统本就不接管 `model_xgb.json`。）

### ③ `live` 的值**不影响任何线上行为**

`load_shadow()`（超智页展示用）读 `current.json`，但**只是展示**。
真正决定线上行为的，是 `models/model_xgb.json` **这个文件本身**（评分接口按 mtime 热加载）。

⇒ **`live: null` 既不报错、也不影响选股**，无需紧急处理。
