# 功能详述

## 选股模式（左视图双 Tab）

**v4.5 起左视图改为双 Tab：AI竞价 + AI 预测**（原"盘中实时"模式因基本无人使用，9/1 起从首页移除；store 的 spot 代码与 PoolView/自选股页保留引用，仅左视图入口停用）。**v4.8（9/5）tab 更名「竞价」→「AI竞价」**（选中态红色高亮，区别于 AI预测）。

| 维度 | 竞价选股 (auction) | AI 预测 (aipick，嵌入) |
|---|---|---|
| 时段 | 9:15-9:31 竞价锁定 | 9:27 预测出榜后全天 |
| 数据 | 竞价字段(f615/f616) + 昨日成交额 | XGBoost 涨停概率 Top 榜 |
| 评分 | 竞价五因子(涨幅34/换手32/异动17/市值11/昨涨6) | ai_prob 涨停率 |
| 筛选 | 竞价条件（剔除ST/停牌、剔除昨日涨停、竞价涨幅≤7%、市值/股价/竞价金额、**分数≥80分**） | 市值/竞价金额/涨幅/涨停率≥50%（前端规则条可调） |

> **v4.11.19 筛选去重**：首页「涨停率 ≥□%」与「评分 ≥□ 分」筛的是**同一个字段 `probability`**，
> 已合并为一项「**分数 ≥□ 分**」（绑定 `scoreFloor`，沿用单阈值硬门槛，默认 80，0=不限），
> **选股名单零变化**。⚠️ `probLt/confLt` 无 UI 入口但仍按默认 65/65 传后端 →
> 分数调到 **65 以下**时"双低"判据会额外生效（既有耦合，解耦需改后端）。
| 名单 | **9:30 前锁定后恒定** | 每日最新报告（历史回看走导航「历史回看」页 AI 预测 tab） |
| 落库/推送 | lock 落库 + 推送 | 报告独立存储 |

> **唯一选股链路（v4.11.3，2026-09-11）**：全站选股（首页 refresh / lock / 定时批次 auto_apply）
> 统一由 **`picker.pipeline.run()`** 产出，模块分层 `contract → sources → score/score_factors → filter → pipeline → lock`。
> 此前并行的"老链路"（`scorer.score_all_stocks + apply_filters`）、灰度对拍（`picker/parity.py`、
> `stocks._parity_reverse`）与回滚开关（`settings.picker_lock` / `picker_gray`）**已整体删除**——
> 回滚只能靠 git 回版本，线上无开关可切。改动前请读 `AGENTS.md` 第七节。

**竞价数据源双源并存（v4.11.12，2026-09-12）**：竞价期（9:15-9:25）同时采集两个源，
**只补缺、绝不覆盖**：

| | 东财 push2dycalc（主） | TickPlus fullbid（第二源） |
|---|---|---|
| 竞价涨幅 | f615 | `zf` |
| 竞价额/量 | f616 / f617 | `je`(元, /1e4 得万元) / `jv` |
| 覆盖 | 全市场 ~5500（**会被接口级风控熔断**，9/11 只落 132 行） | 全市场 5551（实测 1.8s，涨幅/额覆盖 100%） |
| 名称/市值/封单 | ✅ f14 / f21 / f117 | ❌ 全缺（由 `mv_cache` + 开盘啦补） |
| 触发 | 每时点 | 仅 `full=True`（时点快照），秒级采样不动 |

合并规则：东财缺失的 code → 补票；东财 `bid_change`/`bid_amt` 为 0 → 补值；
**已有正常值一律不动**（两源口径不同，覆盖会让同一时点出现两套数）。
开关 `settings.tickplus_enabled`（默认开）；**未配 `tickplus_token` 时完全不发请求**。

**流通市值日频缓存（v4.11.12）**：`float_mv`/`name` 是静态基础数据，却原本只能从
当时行情源碰运气拿 —— 东财一挂全市场市值一起没，TickPlus 补进来的票 `float_mv=0`
会被市值门槛当小盘股**全误杀**（补了等于白补）。现三级兜底（新表 `stock_float_mv_daily`）：
① 当日东财 f21/f117（最准，已有值绝不覆盖）→ ② 本表最近一日（≤15 天，超窗拒绝）
→ ③ 腾讯 `qt.gtimg.cn` f44 批量补（**单位亿 → ×1e8 得元**）。东财正常日 0 次腾讯请求。

> **09-13 历史回填**：从 `snapshot_bid`（带值 442577 行）按同一 `(date, code)` 取 **`ts` 最大**
> 那条，经 `mv_cache.save()` 回填 **117713 行 / 22 个交易日（2026-08-13~09-11）**，
> 抽 200 只与源值比对**不一致 0**；`lookup()` 5851 只命中 **5503（94.1%）/ 0.30s**。
> → 熔断日腾讯兜底只需补 ~350 只，**不再触发 `MAX_FETCH=4000` 静默截断**（原会丢 ~1400 只市值）。
> ⚠️ 回填脚本务必**先算完再写库**（本次曾因元组越界崩在计算阶段 → 零副作用；边算边写就得回滚）。

**全市场预计算物化表（v4.11.11，2026-09-12）**：评分 5 因子（竞价涨幅 34% / 换手率 32% /
异动等级 17% / 流通市值 11% / 昨日涨幅 6%）的输入**全部在 9:25 定格**，唯一活字段是实时涨幅
—— 因此全市场评分可以**在开盘前一次算好**。`picker/precompute.py` 在 `system_batch` 9:26 批跑
**之前**执行，把 5557 只的评分与定格字段写入物化表 `stock_score_daily`
（PK `(date, code)`，`INSERT OR REPLACE`）：实测 **1.5s / 覆盖 99.9% / 幂等**。

三条铁律（缺一不可）：① **不由网络可用性漂移**（唯一例外是 `prev_close` 这类静态值）；
② **缺失写 NULL 不写 0**（0 是"实测为零"，NULL 是"未知"）；③ **行数 < 500 不落半张表**。
读写开关分离：`precompute_read`（读侧走物化表）/ `precompute_write`（写侧产出物化表）
**默认全关**，关时行为与改动前完全一致；物化路径**不豁免 `scoreFloor`**
（补丁源全不可用时才豁免，仅原路径）。补丁源合并后由 `_refreeze_locked` 还原定格字段。

**前端本地秒筛（v4.11.13，2026-09-12）**：竞价结束后每只票的评分/可信度都已定格，
用户改筛选条件只是对**同一份结果**换门槛 —— 不必再跑取数/评分。故后端一次性下发
全市场快照，前端在浏览器内完成筛选：

| 环节 | 实现 |
|---|---|
| 接口 | `GET /api/picker/snapshot`（VIP/付费门禁），5557 行 ≈ 2MB，进程内缓存 60s |
| 数据源 | 物化表 `stock_score_daily`（P1 全市场预计算，9:25 后算好） |
| 前端 | `utils/filters.js.pickFromSnapshot` + `stores/stocks.js.loadSnapshot()` |
| 实时价 | 名单定型后走 `/api/quotes` 按需补；**拿不到保留定格值，不写 0** |
| 抢筹标 | 复用 `pipeline.qc_fields`（与后端同口径，不分叉） |

四条边界（缺一不可）：① 开关 `frontend_local_filter` **默认 0**，关闭时只回
`enabled=false`，前端**静默回退**原后端筛选路径 —— 天然灰度，不需前后端同时上线；
② 门禁与竞价异动同级；③ **行数闸门** < 500 行视为不可用，**绝不发半张表**；
④ 过滤规则**逐条复刻**后端 `coarse_filter + apply_filters`（含"竞额降序取前 120"截断
位置与"评分降序 + code 字典序"排序），两侧共用夹具 `tests/fixtures/picker_parity.json`
各跑一份对拍测试。

> **口径坑（改代码必看）**：`bidGt` 是竞价涨幅上限且**无 `>0` 判断**（填 0 = 上限 0% ≈ 全剔），
> 而 `floatMvGt`/`priceGt` **有 `>0` 判断**（填 0 = 不限）—— 同后缀不同语义，必须逐字段照抄。
> 契约版过滤只有 8 步；`chgGt`/`volRatioFloor`/`turnoverFloor` 等实时门槛**契约链路已不检查**。

**未知 ≠ 0（v4.11.13）**：落库 `_safe_num` 把 `None` 兜成 0 是为了绕过 `NOT NULL` 约束
（并保证排序稳定），但 **0 是有业务含义的实测值**，两者混淆会让前端把"没数据"显示成
"实测 0.00%"（9/11 全员现涨 0.00% 事故的表征之一）。闭环做法：落库用 `_num_or_mark`
把**被兜底的键**记入 `batch_stocks.miss_fields`；读侧开关 `history_null_restore=1` 时
把这些键还原为 `null`。前端全链路容错：**未知显示「—」，实测 0 仍显示 0**
（`utils/format.js` 的 `fmtNum`/`pct`/`signed` 统一口径）。两个开关**默认 0**。

**竞价锁定名单语义**：9:30 前 lock 的名单恒定不变（后端 lock 批次为权威 + 本地快照兜底）。9:30 后刷新时名单不增删，只按 code 合并全市场实时行情（spotMap）更新实时涨幅/评分；被筛选条件剔除的票直接移除，条件放行但行情不在榜的标"已跌出"。

**评分门槛 scoreFloor**（v4.10，9/10 主人拍板，全站默认 **80**、条件面板/管理后台可配）：评分低于门槛的票**直接不入选**。与既有 `probLt`/`confLt` 的区别务必分清——

| 机制 | 语义 | 结果 |
|---|---|---|
| `probLt` + `confLt`（双低剔除） | 概率 < probLt **且** 信心 < confLt 才剔除 | 高信心可以救低概率票 |
| `scoreFloor`（单阈值硬门槛） | 不看信心，评分 < 门槛一律砍 | 低分票不给展示机会 |

实现要点：门槛只能放**精筛**（评分之后）——粗筛在评分前跑，拿不到 `probability`；统计键 `score_floor`。默认 80 下 Felix518 原条件 14 只 → 6 只（评分 81~88）。

**降级豁免**（v4.11.7，9/11 修）：补丁源（东财点查 + 腾讯点查）**全部失败**时，候选行只剩 9:25 定格字段——换手/量比/异动/昨日涨幅全缺，算出来的 `probability` 是**保守占位分**（只有竞价涨幅 + 流通市值两个因子可得），不是"这只票差"。若不豁免，`scoreFloor` 会把「点查失败 → 快照行直出保名单」这条降级保命路径整批砍成**空名单**（该路径的设计目标恰恰是"行情源全挂时名单也不为空"）。实现：`FilterContext.score_floor_exempt`，由 `pipeline.run` 在补丁源不可用时置位。**豁免只作用于评分门槛**，板块/ST/竞涨/市值/竞额等硬条件照常生效（有专门用例锁这一点，防"降级=不过滤"）。

**lock 当日幂等**（v4.6，9/2 主人确认语义）：**9:25 后** + 同筛选参数（指纹 = 筛选参数 + markets 集合）的自动 lock（页面加载/重新登录触发）**直读当日批次**返回——不再全量重拉行情/重复落库/重复推送（解决"每次重新登录都重算一次+堆 lock 历史"）；API 返回 `idempotent:true`，前端 toast「✅ 已载入今日锁定名单」。**9:25 前不幂等**（竞价数据未定型，每次进页重算拿最新）；**用户主动点「锁定」带 force=1 强制重算**落新批次；筛选参数改过也不幂等（正常重算）。另 filter 60s 同参去重（`recent_same_filter`），防脚本/手滑反复点应用刷历史批次。

**休市回退秒开**（v4.8，9/5 多用户反馈"关闭平台后再打开首页转圈"）：**9:30 后 / 休市时间**首屏 refresh 在当日无批次（非交易日、当日系统批次为空、当日无手动批次）时，后端 `history.find_recent_reusable_batch` 自动回退 **14 天窗口内最近交易日**的同参批次直读——**关闭前选出的名单直接呈现**（`reusedDate` 标识数据日期，前端 toast「已载入 X 的选股名单」）；参数指纹不一致（用户改过条件）仍走重算；窗口内无任何手动批次才回退最近系统统一批次（空名单批次无直读价值跳过）。生产实测 96ms vs 重算 2.6s+（27 倍）。

**左视图抢筹口径**（v4.5）：**命中右视图竞价抢筹三表并集才打抢筹标**（`get_qiangchou_codes` 合并 list20 竞额强度/list20Chg 9:20→9:25 涨幅/listLast 最后一秒段，30s 缓存，与竞价异动页口径一致）；集合为空/未传回退旧公式（涨幅≥2% 且 竞/昨≥20%）兜底。打标结论**落库 batch_stocks.qiangchou 列**（老库自动 ALTER），9:30 后锁定名单历史回看可显示 🔥。

## 会员体系

**会员专属功能**：竞价选股、AI 预测、竞价异动（3 个入口；原"盘中实时"模式 9/1 从首页左视图移除，store 代码保留供自选股页复用）。**竞价异动为严格门禁**（仅 VIP/付费/管理员，免费/试用任何时段都不可访问）。

- **三层会员（`users.member_level`）**：
  | 等级 | 含义 | 拦截 |
  |---|---|---|
  | 0 | 免费试用（注册送 7 天） | 到期拦截 |
  | 1 | 付费会员（按到期时间） | 到期拦截 |
  | 2 | **VIP**（管理后台指定） | 前端展示按实际 expire_at；业务逻辑视为永久权限 |
- **拦截规则**：竞价选股仅**工作日 9:15-15:00** 对非会员拦截；AI 预测 VIP 门禁见下方章节；竞价异动**任何时段**仅 VIP/付费/管理员可用（`require_vip_or_paid` 依赖，10 个端点统一）
- **新用户**：注册即送 **7 天试用**（`NEW_USER_DAYS`）
- **邮箱认证**：新注册 `email_verified=0` 强制邮箱验证后才可登录（`/api/verify-email` + 重发冷却 5 分钟）；老用户默认已认证；SMTP 未配置自动降级跳过
- **邀请码非必填**：注册时邀请码为空直接放行；填写则**被邀人 +7 天试用、邀请人 +7 天/人**（`INVITE_REWARD_DAYS`，按 max(now,当前到期) 顺延，多邀多得）
- **防刷**：同 IP 24h 注册上限（`REG_IP_DAY_LIMIT=5`）+ 自邀/同 IP 已邀≥3 不发奖励（`invite_reward_blocked`），注册仍成功
- **管理员豁免**：`isMember = isAdmin || !expired`，管理员永远有权限
- **到期判定**：`users.expire_at` 时间戳（0 = 永久）；登录/注册接口返回 `expire_at` / `expired` / `member_level`
- **开通/续费**：管理后台用户列表 ⋮ 下拉 → 永久 / 本周 / 本月 / 季度 / 年 / 自定义到期日（`/api/admin/users/expire`）；**批量设到期**（多选 checkbox → 批量延长/日期/永久）；**等级切换** → `/api/admin/users/member-level`
- **前端标识**：NavBar 显示会员等级徽标（VIP=金 / 付费会员=红 / 管理员=蓝 / 试用 X 天=紫）；`VipGate` 组件拦截（VIP 专属文案）
- **邀请关系**：管理员可看每用户「被谁邀请 / 邀请了谁」（含注册 IP 识别刷号），列表带邀请人列

## 主题与字号

- **切换器位置**：**主题 = 导航栏快捷圆点**（⚫ 深色 / ⚪ 浅色，点击即切，2026-08-18 移出下拉）；**字号 = 右上角账号下拉菜单**（小/标准/大）
- **背景明暗切换**（⚫/⚪）：黑色 / 白色（默认），全站通过 CSS 变量 `--bg-*` / `--text-*` / `--border-soft` 双套主题；涨跌语义色（红涨绿跌）、金银铜、健康灯不随主题变
- **白色主题导航栏**：**红色渐变** `linear-gradient(135deg,#e03a2f,#c62828)`（A股红喜庆，2026-08-17 主人钦定）
- **字号三档**（A / A / A）：小 `0.92` / 标准 `1` / 大 `1.12`，用 `document.documentElement.style.zoom` 整体缩放
- **持久化**：登录用户存服务端 `prefs`（`{ bg, font }`，后端合并保存不覆盖其他字段），未登录存 localStorage；换设备登录自动跟随
- 实现：`composables/useTheme.js` + `NavBar.vue`（主题圆点 + 账号下拉菜单）

### 竞价抢筹双表（核心）

- **左表（9:20-9:25 段）**：开盘啦 Type4 全市场竞价异动 200 只，`抢筹强度 = 竞价净额 / 流通市值 × 100`，过滤 `>5%` 且 `流通市值 ≥ 2亿`；竞价时段实时拉取 + 持久化 `qc_snapshot` 表。**涨幅抢筹**（第二表）过滤链：流通市值≥2亿 + 竞价额>0 + 竞价额≥500万 + 竞价涨幅>2%
- **右表（最后一秒）**：`snapshot_lastsec` 秒级高频采样（9:24:55-9:25:03 每秒一次，ts 记实际时刻），**差值回退算法**：
  1. `9_25 涨幅 − 最新秒涨幅`，|差| ≥ 0.5% → 直接用（最后一秒抢筹）
  2. 差太小（接口延迟导致最新秒已含变化）→ 向前回退：最新秒 − 倒数第二秒，依此类推取第一个大差值
  3. 全部差值小 → 取最大差（弱信号）；无秒级序列 → 回退 9_24 时点兜底
- **竞额/昨比列**：双表「竞价换手」列改为「竞额/昨比」= 今日竞价额 ÷ 昨日全天成交额（`fetcher.fetch_yesterday_amounts` pair[0]），≥20% 橙色高亮 / ≥10% 黄色
- **非竞价时段**：读库展示今天已选结果（不丢失）；**实时模式自动回退**：今日无快照时自动回退最近交易日（盘前/周末可看昨日数据，`date` 字段透出实际日期）

## 概念开盘啦化（全部股票）

选股列表 / 历史回看 / 竞价异动的**所有股票概念**统一替换为开盘啦风格（短板块名顿号分隔，如 `机器人概念、股权转让、汽车零部件`），替代东财 f103 逗号长串。实现为**双层覆盖**（`kpl.apply_board_concept`）：

1. **榜单层（快）**：开盘啦 5 路榜单接口合并（连板梯队/涨停委买/爆量/热点股/9:25 快照）→ 一次拿到 86+ 只热点股板块
2. **按股层（全）**：对榜单未覆盖的股票逐个调 doc94 `GetStockIDPlate`（个股全部相关概念板块）→ **100% 覆盖**；`ThreadPoolExecutor` 分批并发 + 每只 1 天缓存

**覆盖范围**：竞价选股（落库前覆盖 → 页面/历史批次/推送统一）、盘中选股、历史批次明细、历史聚合查询。**前端只显示前 2 个概念**（`shortConcept`），完整列表 hover title 查看。

**概念定时落库（v4.1）**：`stock_concept` 表 + `concept_refresh` 每半小时从所有竞价/上榜实时接口采集批量写库（覆盖盘中新增，如竞价爆量 407 只）；竞价各接口改从库读（`apply_board_concept_db`），不再每次请求实时逐股查 → 全表格概念 100% 覆盖且低延迟。

**防限流设计**（踩坑修复）：`_call` 加全局信号量（并发 3），失败结果不缓存（避免 1 天空串缓存），按股查询分批 20 只/批。

### 落库任务时刻与自愈（v4.11.16，2026-09-13）

历史落库曾**自上线起长期空转**（`limit_history` 停更 12 个交易日、`lhb_history` 停更 20 个），
根因不是"调度没跑"，而是**采集时刻早于上游发布**，且失败后既不重试也无次日补救：

- **时刻修正**：涨停/炸板（上游**选股宝 flash 池**，当日数据 15:50 后才发布）与龙虎榜
  （盘后公布）统一由 **15:30 → 18:30 晚间窗**（18:10~18:50），龙虎榜单独占 18:30~18:40。
- **失败退避重试**：`_fired` 改为**成功后才置位**，窗口内失败按 300s 起、翻倍、上限 1800s 重试，
  并加 `_running` 防重入 —— 旧逻辑"起线程即置位"= 窗口内只试一次，上游一迟就当天废弃。
- **失败回滚**：龙虎榜 `setnx` 占锁后判空**补 `store.delete`**（旧逻辑不释放 → 一次空即当天全废）。
- **次日盘前自愈**：新增 **09:00~09:05 补救窗**（避开 9:15 竞价主流程），回溯最近 7 个自然日，
  按 `INSERT OR REPLACE` 幂等补齐 `limit_history` / `lhb_history` 缺失交易日
  → 晚间窗因重启/节假日错过时，次日开盘前自动兜住，缺口不再累积成长缺口。

### 日K 缓存新鲜度与股性画像（v4.11.16 修 + 09-13 生产重建）

- **原缺陷**：`_kline()` **命中缓存即永久返回、无过期判断**，而 `rebuild_profiles()` 默认
  `refresh_kline=False` → 日K底座永久冻结在首次写入时刻（生产实证 `stock_kline` 与
  `stock_temper_profile` 的 `ts` **全部 = 8/27**，相差 11 个交易日）。**只调时间窗治不好**，
  必须修 TTL。
- **修复**：末根日期 < 期望最近交易日（收盘 15:05 前取上一工作日）→ **回源**；
  解析不出末根日期时按"新鲜"处理（避免异常形态下全量回源打爆上游）。
- **生产重建（09-13）**：一步 `rebuild_profiles()` 完成治本 —— **3978 只 / 861.6s / 失败 0**，
  日K **回源 3951/3978**（TTL 生效后命中率 99.3% → 全量回源），`ts` 全部刷新。
  → 样本 002790 瑞尔特：`zt_count`（近一年累计**封板次数**）**4 → 8**、`max_zt`（最大**连板高度**）仍 **4**。
  ⚠️ 两个字段语义不同，汇报"几板"必须写清是次数还是高度。
- **运维提示**：跨机外推耗时**乘 2 倍安全系数**（测试机 0.105s/只 → 生产 0.217s/只）；
  生产 DB 是 WAL，在线大批量写不阻塞读，此类重建可在线跑。

> 🔴 **2026-09-14 字段语义纠正（盘中实测钉死，推翻 9/13 结论）**：该接口 `zrtj` 系字段是**天级基准**、`zrcs` 系才是**时点成交** —— `s_zrcs` = 昨日**同一时点**（**基准取它**）、`s_zrtj` = 昨日**全天**、`s3_zrtj` = 前 3 日**全天均值**（**≠ 同期**！前 3 日同期只能从 `trends` 末行第 4 列取）。9/13 初版把 `s_zrtj`/`s_zrcs` **判反**，基准实际取了昨日**全天**量 → 面板显示「缩量 9505 亿」（**虚高 6.6 倍**，正确应为 1446 亿）。**根因：9/13 在周日验证** —— 收盘后「同期」退化为「全天」，两字段**完全相等**，根本区分不出来。已加**自检**：解析时若「同期 > 全天」（盘中不可能）即丢弃同期值并告警；并加了语义方向断言防回归。**教训：字段语义只能在活跃窗口（盘中）实测钉死。**

**昨比（昨日成交额）＝ 收盘落库 + 全天读库**（2026-09-10 新机制，替代原四级兜底链）：每交易日 **15:10** `yday_prewarm(stage="close")` 批量拉全市场写入 `yday_amount` 表（**按 code 覆盖写**，`INSERT OR REPLACE` 兼容 CentOS 7 SQLite 3.7）；此后全天 `_yday_hydrate_from_db` **直接读库（零网络）**，只有库里没有的（新股/停牌/落库任务未跑）才走实时链 **东财日K → 腾讯 `qfqday`（`_yday_fallback_tencent`，真实成交额万元）**。**盘中预热(stage="open")不落库**——那时 T=前一交易日，写库会污染语义。读库对 `tdate` 超 5 天（长假/停更）与空 `amount` 的行过滤，读库异常自动回落实时源。→ 运维注意：机制**从首次收盘刷新起才生效**，此前 `yday_amount` 为空即走实时源；**腾讯备源是必需的**，否则 push2his 风控期会落 0 行、机制空转。
