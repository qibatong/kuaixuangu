## 一、现状诊断

### 1.1 底层：三处割裂（不是样式问题，是架构旁路）

| 对比项 | 主站其它页面 | 超智预判页（现状） |
|---|---|---|
| 运行位置 | nginx `/` → 静态 dist → 主站 SPA | nginx `location /chaozhi/` → `proxy_pass 127.0.0.1:8020` |
| 服务形态 | `kuaixuan.service`（uvicorn 8010，systemd 托管） | 手写 `gunicorn -w1 -b 127.0.0.1:8020 server:app --daemon`（**无 systemd，重启即失联**） |
| 技术栈 | Vue 3 + Vite 单页应用 | Flask + 单文件 `static/index.html`（540 行，内联 CSS，含 echarts） |
| 数据契约 | `/api/*`，统一走 `src/api/request.js` 封装 | `/chaozhi/api/snapshot`，私有 JSON 契约 |
| 鉴权/会员 | Bearer token + `get_uid`，401 自动踢登录 | **无鉴权**，URL 直达即可看全量内容 |
| 产物/回滚 | 线上 dist + `dist.bak_*` 回滚点 | `/opt/chaozhi` 目录，无回滚点、无版本 |

关键证据：
- `frontend/src/views/ChaozhiView.vue:33` 现在是 `<iframe src="/chaozhi/?embed=1">` —— 主站这个路由已经退化成一个 iframe 壳（**该文件当前有未提交修改**，`git status` 显示 `M`）
- 该 iframe 用 `calc(100vh-150px)` 撑高，不继承 App.vue 的 `.has-tabbar` 底部安全区，手机上会出现**双层滚动**

### 1.2 布局/样式：与主站的第二套设计语言

对照主站基准（`App.vue` + `styles/main.css` + `useNavGroups.js`）：

| 项目 | 主站基准 | 超智页现状 | 影响 |
|---|---|---|---|
| 外壳 | `NavBar` / `GroupNav` / `AppTabBar` / `Watermark` / `PwaBar` | **全部没有** | 无顶栏、无分组导航、无手机底栏、无水印 |
| 容器 | `.page-shell`（唯一定宽） | 自建 `max-width:1200/900/560` | 与主站留白、栅格不一致 |
| 断点 | 5 档规范（业务主流 768 / 480） | 只有 1200/900/560 三处写死 | 不在规范内，会被 `breakpoint_guard` 拦 |
| 卡片/标题 | `xx-card-head` + `--fs-xl` 区块标题 | 自写私有类（`.sec-title` 等） | 同等信息层级两套写法 |
| 颜色 | CSS 变量（`--up/--down/--bg-panel/--r-pill…`），跟随深浅色主题 | 硬编码十六进制 | **切浅色主题会失效**，深色/浅色不一致 |
| 数据层 | `request()` 封装（token、401 处理、缓存去重） | iframe/私有 fetch | 会员态埋点、配额、报错统一处理全部失效 |

### 1.3 数据真实性核验（这块最重要）

**先更正我上一轮的判断**：我此前认为"指数点位/竞价全量/板块资金都没有数据源"，**这个判断是错的**——`realdata.py` 认真接了主站后端服务，比我以为的齐全。

✅ **已确认接真实数据**（`/opt/chaozhi/realdata.py:299-320`）：

| 区块 | 后端来源 |
|---|---|
| 情绪/资金/机会清单 | `app.services.chaozhi.build_overview` |
| 市场简报、连板梯队、昨日涨停表现、热点板块、板块个股 | `app.services.kpl` |
| **三大指数** | `app.services.meoz_client.index_snapshot` ← 真有这个服务 |
| **竞价 9:25 快照** | `app.services.auction_snapshot.load_snapshot_full` |
| 主线的"状态/健康度"文案 | 由板块涨幅+资金规则推导（`_bstate` / `_bhealth`），可解释 |

⚠️ **派生/伪装，必须处理**：

1. **四维雷达是伪装的**（`realdata.py:388-394`）——四个维度全部由同一个 `score` 线性算出：
   ```python
   "基本面": min(100, int(60 + (sx - 60) * 0.5)),
   "资金面": min(100, int(55 + (sl or sx) * 0.3)),
   "技术面": min(100, int(50 + sc * 0.4)),
   "情绪面": min(100, int(sc)),
   ```
   四根轴**完全相关**，画成雷达图看着像四个独立维度，实际零新增信息——用户会据此做多维判断，但它在骗人。
2. **策略标签是硬编码规则**（`realdata.py:385`）：
   ```python
   strat = "打板" if (tag == "关注" or isLimitUp == 1) else ("趋势" if sc >= 85 else "低吸")
   ```
   不是模型输出。页面却自称"LGB+XGB 双模型输出"。
3. **演示数据回退是隐式的**（`server.py:245-255`）：服务启动时先 `SNAPSHOT = build_snapshot()` 生成一套演示快照（内含"合成训练面板"），若 `get_snapshot()` 整体抛异常就 `return jsonify(SNAPSHOT)`。前端**看不出**自己拿到的是演示数据。（好消息：`realdata` 内部 `_call()` 是分块容错，单块失败只缺块、不会整体退化。）

🧨 **另有一处口径差异待确认**：页面显示涨停 52 / 最高连板 7 板，而库里 `limit_history`（09-30）是涨停 56 / 最高 5 板。来源是实时 `kpl` 与盘后落库 `limit_history` 两套口径，需定哪套为准。

## 二、目标形态

**超智页 = 主站里的一个普通路由页**，与其它页面完全同构：

```
/chaozhi  →  ChaozhiView.vue（原生 Vue，无 iframe）
外壳      →  App.vue 自动提供 NavBar / GroupNav / AppTabBar / Watermark
数据      →  GET /api/chaozhi/home   ←  backend/app/services/chaozhi.py
鉴权      →  Depends(get_uid)（会员/配额自动生效）
样式      →  .page-shell + CSS 变量 + 768/480 断点，跟随主题
```

可选方案对比：

| 方案 | 做法 | 工期 | 优点 | 缺点 |
|---|---|---|---|---|
| **A（推荐）** | Flask 下线，逻辑迁入主站 services，前端重写 | 5 天 | 完全同构、鉴权/埋点/主题自动生效、单一运维 | 工作量最大 |
| B（折中） | Flask 只留 `/chaozhi/home` 吐 JSON，Vue 负责渲染 | 3 天 | 改动小 | 两套服务仍要运维，鉴权要额外代理 |
| C（保守） | 维持 iframe，只对齐 CSS token + 加鉴权 | 1 天 | 最快 | 双层滚动、底栏遮挡、埋点缺失仍在 |

**推荐 A。** B/C 只是把症状藏起来，半年后又会长出第二套"某个页面"。

**字号按「角色」而非「档位」分配（2026-10-06 四改）**

主人反馈「很多地方字体大小不一致」。查下来是我的方法有问题：**上一轮我只做了值域收敛**——
保证每个字号都落在规范 8 档内（所以闸门能过），但没规定「同一种东西必须同一档」。
单看每个值都合规，放一起就不齐（主数字一个 24px 一个 28px、胶囊一个 12px 一个 13px）。

补上**角色映射表**，同类元素强制同档：

| 角色 | 令牌 | 值 | 覆盖元素 |
|---|---|---|---|
| 区块标题 | `--fs-xl` | 18 | `.sec-t` `.fold-t` |
| 小标题（卡片/行首） | `--fs-md` | 15 | `.board .bt` `.nav-brand-name` `.nav-logo` `.lad-n` |
| 主数字（区块级大数） | `--fs-display` | 24 | `.kpi .v` `.gauge .num` |
| 次级数字（卡内/表内） | `--fs-lg` | 16 | `.sc` `.ix-v` `.kpi .v.xs` |
| 正文 | `--fs-base` | 14 | `body` |
| 表格正文 | `--fs-sm` | 13 | `table` |
| 导航项 | `--fs-sm` | 13 | `.nav-tabs a` `.group-nav-item` |
| 标签（胶囊/标记） | `--fs-xs` | 12 | `.pill` `.ltag` `.chip` `.tab` `.btn` `.health` `.ix-p` |
| 说明文字 | `--fs-xs` | 12 | `.sec-sub` `.prov` `.kpi .k` `.cd` `.cp` `.ladder` `.lrow` `th` `.fold-*` 等 |

据此修掉 3 类不一致：温度计主数字 28→24（对齐 KPI 主数字）；机会清单评分与「规模」值 15→16（对齐卡内数值）；竞价龙头胶囊与梯队档位名 13→12（对齐标签），
其中梯队行首「七板/首板」判定为**行首小标题**而非标签，归入 15px —— 12px 会和旁边的辅助字糊在一起，行首就没了标识作用。

`_tag` 规则：`任一模型 <60 ⇒ 谨慎`，而当日最高票是 `min(57,66)=57` ⇒ 22 只全部「谨慎」。
