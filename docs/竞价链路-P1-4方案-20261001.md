## 二、🔴 为什么必须"成组改"：一条时间链 + 三条不变式

**时间链**（全部是"当日绝对秒"，都含 `9*3600`，比较时两侧不得再减 `9*3600` —— 这里历史上出过静默失效事故）：

```
09:15:00 闸门关闭(时间维)  09:24:00 竞价类首枪 + 抢筹轮采开始
09:25:20 ←目标 定格单枪(写 9_25 终值) → 同轮: 自算量比回填 → 触发 AI(绕过窗口)
09:25:35  开盘啦类第二枪(auction_daily_history, 另一张表)   ≤09:25:20 抢筹轮采上界
```

**三条不变式**（今天的代码靠散落的注释维系，没有任何一处代码保证；本次要**变成断言**）：
1. `_BID_QC_UNTIL_SEC ≤ _BID25_FREEZE_SEC`（抢筹轮采不得晚于定格）
2. `_NETFILL_HARD_END_SEC ≤ _BID25_FREEZE_SEC`（净额补采硬停 ≤ 定格；"截止后不再改数据"）
3. `_BID_HIST2_SEC < _BID25_FREEZE_SEC`（**开盘啦第二枪必须早于定格** —— 见第五节冲突①）

🔴 **只改定格、不改闸门 ⇒ 收益为 0**：闸门是**双闸门**（时间维 → 快照维，`api/stocks.py:_pick_blocked_reason`），
时间维到 09:26:30 才放行，用户 09:25:2x 打开仍被拦（有护栏用例 `test_pick_window_guard.py:83-84` 钉着：09:26:30 拦 / 09:26:31 放）。
