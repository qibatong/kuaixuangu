docs(diagnosis): 东财 clist 分页越界误判 → 竞价窗口熔断自锁（P0，仅诊断未改码）

起因：主人质疑「老是说服务端被限流、采集定格快照有异常却找不到解决方案」。

结论：**不是限流，是我们自己的 bug**。
- `SPOT_MAX_PAGES=30` 固定打 30 页，各 fs 真实页数 = `ceil(total/200)`
  （主板 18 / 创业 8 / 科创 4）⇒ 越界页恒返 `rc=102 / data:null`
  （东财正常"翻到底"语义），被 `_fetch_clist_page` 当异常抛出。
- 于是 cyb/kcb 触发 `done_fail >= done_ok` ⇒ ①该分区整批放弃走腾讯
  ②`_record(False)` + `down_threshold=1` ⇒ 熔断 60~600s。
- 实测：**每天 09:15:12 熔断 → 09:29 恢复**（9/17 546s、9/18 535s，
  启动时刻完全一致），完整覆盖 9:15~9:29 竞价窗口。
- 9/18 09:25:28 定格采集三分区齐报「熔断中」→ 东财 0 只 → 开盘啦 277
  + TickPlus 5555（补值0项）⇒ 名单权威数据非东财口径，f630 必然全 0。

铁证：
- 9/18 分页失败 9332 条清一色，页号只在 19~30（1~18 零失败）
- 逐页实测：越界页起点精确等于 `ceil(total/200)+1`
- 串行 150ms 慢速仍复现 ⇒ 确定性，与频率无关

修复方案（未实施，待放行）：
1. `_fetch_clist_page`：`rc==102` → 返回 `[]`（"到底"语义），不抛异常
2. `fetch_eastmoney_all`：页数按首页 `total` 动态计算
3. `eastmoney_clist.down_threshold`：1 → 3

预期收益：日志噪音 9332/天 → 0；cyb/kcb 回归东财真源，f630 非 0 从 0 → 928 只
（880 只 ≥3 档票从"被当 0 档"恢复）；竞价窗口不再撞熔断。
